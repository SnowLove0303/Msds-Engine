# 引言：什么是“覆写规范”？为什么最容易被意外篡改？

在 MSDS 智能生产系统中，所谓**“覆写规范”（Overwrite / Override Invariants）**，指的是：
> **“当把客户源文件中的化学事实提取出来，灌入官方标准 Word 模板槽位时，哪些单元格必须按什么特殊规矩写入、哪些绝不准动、哪些必须按特殊逻辑转换的强制性铁律。”**

这套规范之所以最容易被后来的 Agent 或维护人员“自以为是地意外篡改”，是因为**其中有大量“表面看起来极度反常识、反直觉，但在化学法规、企业规范或 Word 底层 XML 几何上却是法定硬性要求”的特殊逻辑**：
- 例如：Section 8 为什么必须把源 8.1 填进模板 8.2，源 8.2 填进模板 8.1？
- 例如：Section 1 为什么“产品名称”必须故意留空，而“中文名称”要拼装型号？
- 例如：Section 2 为什么源文件没写，危险分类下也必须强制保留 P405 与 P501？
- 例如：Section 9 为什么是全系统唯一一个允许 Agent 动态修改标签文本的特权节？
- 例如：Section 11 为什么删列后必须做 `gridSpan="3"`、设置 6262 dxa 并强行移除 XML 中的 `<w:vMerge>`？

如果后续维护者缺乏全局视野，仅凭大模型通用的“代码洁癖”或“主观直觉”去优化，就会把这些法定规则误判为“Bug”或“冗余代码”从而擅自删改，导致灾难性的合规事故。

# 第一篇：全局强制覆写规范（全篇 16 节与 8 大交付物统一铁律）

这些规则是跨越 16 个章节以及 8 大交付物矩阵（4 份 DOCX + 4 份 PDF）的最高宪法：

### G-01 权威母版原位血缘克隆 (In-Place Clone)
- **通俗解释**：
  绝不从空白文档重新画表格，必须从官方标准母版（`正式模板_MSDS_CN_冠志.docx` / `正式模板_MSDS_EN_冠志.docx`）进行纯字节级新鲜拷贝，然后只在模板预留的可写槽位中“原位覆盖填写”。
- **为什么必须这样写**：
  官方母版中内嵌了企业标准的页眉页脚动态域代码（`PAGE / NUMPAGES`）、受控的边框网格、单元格内边距和跨页防断行控制。任何程序如果试图从空白文档“仿形画表”，生成的表格必然发生列宽错位、打印跨页溢出。此外，**中文交付物与英文交付物必须中英同源，绝对严禁将中文生成的 Word 直接翻译成英文 Word**（直接翻译会导致英文版丧失英文母版的专业版式并产生机翻幻觉）。
- ⚠️ **防篡改警示**：
  严禁任何重构尝试调用“新建空文档 -> 循环添加表格”逻辑。

### G-02 破坏性 API 绝对禁令 (底层 XML 保护)
- **通俗解释**：
  往单元格里写字时，**绝对禁止直接调用 `cell.text = ...` 或 `paragraph.text = ...`**！必须复用原段落内的 run 节点，只替换文本值。
- **为什么必须这样写**：
  直接对单元格或段落赋值，在 Word 底层会瞬间**把原有的 300 dxa 行距、Arial 12pt 字体、居中对齐、行高、边距等全部清空抹杀，退化为默认 Normal 样式**，导致全篇排版崩坏。
- ⚠️ **防篡改警示**：
  代码中遍历 XML 段落和 run 的逻辑虽然看起来繁琐，但绝对不能被改成看似简洁的一行 `.text = "..."`！

### G-03 二元排版层级铁律（标签 vs 填写值）
- **通俗解释**：
  表格里的每一个字必须明确归入两类，黑白分明：
  | 项目 | 标签 (Label) | 填写值 (Value) |
  | :--- | :--- | :--- |
  | **加粗状态** | **必须强制加粗**（底层 XML 注入 `<w:b/>`） | **绝对不加粗**（必须剥除 `<w:b/>`） |
  | **字体族与字号** | 中文宋体 / 英文 Times New Roman，**12pt（小四号）** | 中文宋体 / 英文 Times New Roman，**12pt（小四号）** |
  | **行距参数** | 严格锁定为 **300 dxa** | 严格锁定为 **300 dxa** |
  | **缩进与对齐** | 复合多行标签挂载 **420 dxa 悬挂缩进** | 常规顶格，无悬挂缩进（Section 3 除外） |
- **为什么必须这样写**：
  这是整份 MSDS 视觉层级与工业级排版的核心。如果填写的值被误带上加粗，或者标签被弄成常规体，整份文件在国际海关与审核机构眼中会被直接定性为不合规粗制草稿。
- ⚠️ **防篡改警示**：
  模板原本的值单元格若带有加粗格式，覆写引擎必须主动剥除 `<w:b/>`，绝不能顺带把模板的加粗属性继承给新内容。

### G-04 预清空防污染协议 (Clean Slate Protocol)
- **通俗解释**：
  在把新产品的化学事实写入模板前，必须先执行一次清空，但**仅清空值单元格（Value Cells），绝对禁止清空标签单元格（Label Cells）与表格第 0 行标题**。
- **为什么必须这样写**：
  标准母版里残留着上一代基准产品的示例数据（如 `PEA-4139`、示例毒理数据、示例接触限值）。如果不预先清空，新产品未提及的字段就会把旧产品的示例数据残留下来，造成新旧数据“并集污染”，酿成化学虚假陈述大祸！但如果清空过了头，把标签格给清空了，表格结构瞬间毁损。
- ⚠️ **防篡改警示**：
  清空必须有精确的槽位白名单，严禁粗暴地对整个表格做全部单元格清空。

### G-05 零臆造红线与规范缺失表达
- **通俗解释**：
  严禁凭空捏造 CAS 号、浓度数值、危险分类、毒理数据；源文件没有提到的项，**绝对不准在 Word 里写“源文件未提供/客户未提供/报告未注明”等技术汇报废话**！
- **为什么必须这样写**：
  化学品安全技术说明书是法定交付件。出现“客户未提供”这类文字会让整份 MSDS 失去法律公信力。系统对缺失内容有严格判定：
  - 属于允许删行的项目（如 Section 9 无数据理化项、Section 8 无数据限值块）：整行安全删除抑制，保持版面干净；
  - 属于法定固定槽位（如 Section 2 象形图无危险、Section 10 无危险反应）：规范填报“无”、“无数据资料。”或“Not applicable.”，严禁留空或写废话。
- ⚠️ **防篡改警示**：
  不要为了展示“系统抽取状态”而把内部审计日志话术写进客户看到的交付文档中。

### G-06 双主体 5 项白名单差异硬约束
- **通俗解释**：
  同一个语言版本下，广州冠志版本与英德国彩版本，**只允许以下 5 项信息存在差异**：
  1. 供应商公司名称；
  2. 供应商地址；
  3. 联系电话；
  4. 传真号码；
  5. 页脚公司署名。
- **为什么必须这样写**：
  两家公司销售的是完全相同的化学品实体，其危险分类、理化特性、毒理学指标必须 100% 字节级一致。如果同一批号的产品在两份文件里出现不同的 pH 值或不同的急救措施，会构成严重法规缺陷。
- ⚠️ **防篡改警示**：
  系统必须遵循“单事实建模”派生，严禁针对两个公司分别跑两遍提取运算，防止产生数据漂移。

### G-07 表格几何拓扑自愈与悬空合并属性清理 (normalizeRowGeometry)
- **通俗解释**：
  当我们在表格中删除了某一列、或者把原本的多列复合行收敛成单列值时，必须调用自愈中枢：把末尾值单元格宽度强制扩宽至 **`6262 dxa`**，挂载 **`gridSpan="3"`**，并且**必须在底层 XML 中彻底删除所有悬空的 `<w:vMerge>` 标签**！全行宽度严格锁死为 **9781 dxa**。
- **为什么必须这样写**：
  微软 Word 对于 XML 表格的合并属性极度敏感。如果一个单元格原本是垂直合并（`vMerge`），后续的行被删除了或者列结构变了，这个悬空的 `vMerge` 会导致 Word 在渲染时把这一行的右侧格子全部压缩挤扁成一条细缝（宽度为 0），排版严重错乱。
- ⚠️ **防篡改警示**：
  在 `docx-engine.js` 中的 `normalizeRowGeometry` 与 `applySemanticOverrides` 代码块是 Word 表格的“生命支撑系统”，严禁为了“简化代码”删掉底层 XML 清理步骤。

### G-08 英文交付物“零中文”强门禁
- **通俗解释**：
  所有生成的英文版 MSDS（冠志英文、国彩英文），全篇文档中**中文字符数必须严格为 0**（基于正则 `[\u4e00-\u9fa5]` 校验，包括中文逗号句号都不允许）。
- **为什么必须这样写**：
  英文版面向国际客户与外国海关，残留哪怕一个中文“水”或“广州”，海关系统就会直接打回退运。
- ⚠️ **防篡改警示**：
  严禁将“零中文”门禁当成软性警告忽略，一旦检测到非 0 必须硬性阻断交付。

# 第二篇：16 个 Section 局部强制覆写规范（分节避坑雷区全览）

每个章节都有其专属的业务特例与法定要求，局部规则是对全局规则的收紧，绝对不可放宽：

### Section 1: 物料及供应商标识 (Identification)
- **法定槽位规矩**：
  - **首格产品型号绑定**：表格第 1 行第 1 格必须强制写入纯净的产品型号（如 `PU-202C`）。
  - **产品名称留空特权**：中文版“1.1 化学品名称”下的**“产品名称”必须按企业规程保持留空**（绝对不能填型号）；而**“中文名称”必须强制拼装为：`产品中文品名 + 半角空格 + 产品型号`**（例如：`水性聚氨酯树脂 PU-202C`）。
  - **英文版品名评审规范**：`Product name` 必须为过审的专业英文名 + 半角空格 + 产品型号（如 `Waterborne Polyurethane Resin PU-202C`），化学范畴严禁随意窄化。
  - **页脚标识规范**：页脚唯一识别码必须强制写入 `<MODEL>-MSDS`。
  - **供应商信息独占去重**：若源文件在第 16 节分散写有电话、地址，系统必须强制将其提取提升至第 1 节，并在第 16 节予以去重清除。
- ⚠️ **后人最容易改错的雷区**：
  看到“产品名称”单元格是空的，自以为是个 Bug，顺手写了代码把产品型号填进产品名称里。**这是严重违规行为，必须保持留空！**

---

### Section 2: 危险性概述 (Hazards Identification)
- **法定槽位规矩**：
  - **P405 + P501 强保留法定兜底**：防范说明无论源文件是否遗漏，凡属危险品分类，**必须强制保留 `P405（加锁存放）` 与 `P501（废弃处置）` 编码与规范语句**。
  - **一码一行保序原则**：每个 H 语句、每个 P 语句（含 `P305+P351+P338` 联合码）必须各占一个独立逻辑行，严禁多条合并成一段。
  - **P 语句四大块结构化**：P 语句必须在值格内归入“预防措施”、“事故响应”、“安全储存”、“废弃处置”四个小标题块，空组安全抑制，非空组保留标题。
  - **2.2 标签要素行结构保护**：2.2 标题大行作为容器行，值格必须留空继承，绝对不能把整行删掉。
  - **信号词槽位纯净度**：信号词格只接受“危险/警告/无”，**严禁带入“信号词：危险”前缀**。象形图格若为非危且无图，统一规范填写“无”。
  - **S2.8 五大健康危害独立路由**：吸入、食入、皮肤、眼睛、症状体征各为独立事实，缺席的路由留空整行删，禁止把总论“未被分类”抄进具体路由。
- ⚠️ **后人最容易改错的雷区**：
  后续 Agent 以“源文件里没有 P405，我们追求 100% 源保真”为借口，把 P405/P501 删除了，导致文件违反危化品标签国标要求！

---

### Section 3: 成分/组成信息 (Composition/Information on Ingredients)
- **法定槽位规矩**：
  - **三列数据强制水平+垂直双居中**：成分名称、CAS 号、含量百分比三列单元格，底层 XML 必须强制注入 `<w:jc w:val="center"/>` 与 `<w:vAlign w:val="center"/>`。
  - **一组分一物理行**：每一条组分必须独占一行物理行，严禁多个组分用软回车挤在同一个格子里；组分数超过模板预留槽位时，必须原位克隆样式行。
  - **混入数据剥离流转**：若源文件组分表里附带了危险分类、急救说明，覆写时必须将其剥离至第 2 节或第 4 节，严禁留在成分格内。
- ⚠️ **后人最容易改错的雷区**：
  全局规则规定“值文本默认左对齐”，后人自以为是地认为 Section 3 居中是“不统一的坏味道”，顺手改成了左对齐，破坏了成分表的美观排版。

---

### Section 4 ~ 7: 急救、消防、泄漏、处置
- **法定槽位规矩**：
  - **Section 4（急救）**：必须分流至皮肤接触、眼睛接触、吸入、食入四个独立槽位，严禁把长篇大论整段堆在首格。
  - **Section 5（消防）**：严格区分“适用的灭火剂”与“不适用的灭火剂”；英文版标题固定为母版 `5.Fire fighting measures`。

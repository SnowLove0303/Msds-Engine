# 第一篇：全局通用规范（全篇必须遵守的大原则）

这些规范是覆盖整份文档的“最高宪法”，无论在处理哪一个章节，都必须无条件服从。

### 1. 8 格式全套标准交付规范
- **通俗解释**：每做完一个产品型号的 MSDS，最后必须交付齐齐整整的 **8 个文件**（不多不少）。
- **具体清单**：
  1. `[型号] msds_CN 冠志.docx`（广州冠志 · 中文 Word）
  2. `[型号] msds_CN 冠志.pdf`（广州冠志 · 中文 PDF）
  3. `[型号] msds_EN 冠志.docx`（广州冠志 · 英文 Word）
  4. `[型号] msds_EN 冠志.pdf`（广州冠志 · 英文 PDF）
  5. `[型号] msds_CN 国彩.docx`（英德市国彩 · 中文 Word）
  6. `[型号] msds_CN 国彩.pdf`（英德市国彩 · 中文 PDF）
  7. `[型号] msds_EN 国彩.docx`（英德市国彩 · 英文 Word）
  8. `[型号] msds_EN 国彩.pdf`（英德市国彩 · 英文 PDF）
- **核心逻辑**：底层以两份官方标准母版（CN 冠志与 EN 冠志）为基准，通过“预设派生引擎”瞬间自动注入英德市国彩的主体信息（公司名、英文名、地址、电话、邮编），保证双主体、双语言全覆盖。

### 2. 源文件无损留存底线
- **通俗解释**：客户给的原始资料是无价凭据，严禁直接在客户原文件上盲改。
- **具体做法**：只要流水线或系统接收到客户的源文件（例如 `PU-202B msds_CN 冠志.docx`），在动工前系统必须自动复制一份命名为：
  - `[型号] msds_CN 冠志_源文件留存.docx`
  - `[型号] msds_CN 冠志_源文件留存.pdf`
- **目的**：不论后续发生任何意外、争议或审计复盘，永远有一份原汁原味的历史证据可供对质。

### 3. 英文版“零中文”强门禁
- **通俗解释**：给国外客户或外贸海关看的英文版 MSDS，全篇绝对不能漏掉任何一个中文字符（连一个中文标点都不行）。
- **检测机制**：
  - 导出英文交付物前，系统会自动扫描文档内的每一个字（基于中文字符正则 `[\u4e00-\u9fa5]`）。
  - **红线要求**：中文字符数必须严格为 **0**。只要发现残留（哪怕是源文档遗留的“广州”、“水性”或者中文逗号“，”），立刻触发熔断报错，禁止交付。

### 4. 表格排版“二元分类法则”（标签 vs 填写值）
- **通俗解释**：表格里的字不能想怎么排就怎么排，必须严格分成两类——**“标签”（Label）**与**“填写值”（Value）**，黑白分明。
- **具体排版特征对照**：
  | 项目 | 标签 (Label) | 填写值 (Value) |
  | :--- | :--- | :--- |
  | **字体加粗** | **必须加粗**（底层 XML 注入 `<w:b/>`） | **绝对不加粗**（必须剥除 `<w:b/>`） |
  | **字体族与大小** | `Arial` 字体，五号字（`12pt` / `24 half-points`） | `Arial` 字体，五号字（`12pt` / `24 half-points`） |
  | **固定行距** | 严格为 `300 dxa`（保证 Word 视觉紧凑专业） | 严格为 `300 dxa` |
  | **缩进与对齐** | 多行复合标签挂载 `420 dxa` 悬挂缩进 | 顶格对齐，无悬挂缩进 |
  | **制表符禁令** | **严禁手写插入 `<w:tabs>` 制表位**（杜绝制表符飞格） | 严禁多余制表符 |

### 5. 表格几何拓扑守恒与自愈中枢 (normalizeRowGeometry)
- **通俗解释**：删掉表格里的某一列后，整个表格不能“塌方”或者右边凹进去一块（像缺了个角一样难看）。
- **核心规矩**：
  - 无论在哪个章节（特别是 Section 11 的 11.7 生殖毒性等多列复杂行），当把原本的“三列/多列”合并收敛为“双列”时，**表格总宽度必须绝对守恒（如 9781 dxa）**。
  - **自愈动作**：删掉中间列后，系统底层自动将右侧的值单元格宽度扩展补齐至 `6262 dxa`，并显式注入跨列标记 `<w:gridSpan w:val="3"/>`，同时**强制剥除残留的悬空 `<w:vMerge>`（纵向合并）标记**，保证右边框 100% 垂直齐平。

### 6. 跨页排版断行全开保护
- **通俗解释**：当表格很长、一页纸装不下的时候，允许表格在两页之间自然分页，不能死板地强制整行表格硬生生挤到下一页导致上一页留下巨大的刺眼大空白。
- **底层规矩**：系统在载入和导出模板时，会全局巡检并彻底清除所有单元格和表格上的禁止分页属性（如 `<w:cantSplit/>`），让长文本和多行数据平滑跨页。

### 7. 全局页眉页脚与物理 XML 注入
- **通俗解释**：页眉页脚不是在正文画画，必须真真切切写入 Word 底层的 `header1.xml` 和 `footer1.xml` 里，打印每一页都有。
- **版式规则**：
  - **页眉 (Header)**：左侧为主标题（`物料安全数据表` / `MATERIAL SAFETY DATA SHEET`）及版本号（`Version: V1.0`）；右上角第一格为加粗的产品型号（如 `PEA-4139`）。
  - **页脚 (Footer)**：
    - 公司名称严格靠左对齐（`<w:jc w:val="left"/>`）；
    - 中间/右侧自适应呈现系统当前最新修订日期（如 `2026年10月08日`）；
    - **页码保护**：完整保护保留 Word 原生的动态域代码（`PAGE` 与 `NUMPAGES`），即显示为 `3 / 5`，绝不能被写死为静态数字。

### 8. 模板防污染与安全清空协议 (Clean Slate)
- **通俗解释**：模板里本来可能印着样例数据（比如参考型号 `PEA-4139` 或示例文字），往里面填新产品数据前，必须把这些示例文字彻底洗干净，绝不能把老数据留下来混在新数据里（“零数据残留”）。
- **底层规矩**：系统执行智能装配前，启动安全清零协议：只保留模板的表格骨架、标题和固定标签，将所有值格（Value Cells）清空，源文档没有提到的项坚决不瞎编（“零臆造”）。

### 9. 前置双清单确认门禁与 VS Code 两栏比对检阅
- **通俗解释**：Agent 或系统改动代码前，必须先列清单向人工请示；改完之后，人工必须在 VS Code 原生双栏比对窗口里审阅过，按确定才算数。
- **双清单制**：
  1. **清单 1（拟变更范围）**：改动哪些文件、涉及什么函数、怎么验证；
  2. **清单 2（保持现状承诺）**：向用户明确保证绝不触碰、绝不删改原有的哪些正常业务逻辑。

### 10. 代码级防篡改封印标记机制 (@ANTIGRAVITY_INVARIANT_LOCK)
- **通俗解释**：对于经过反复调试确认的极其核心的特殊业务代码，打上“封印”标记，任何人或 Agent 来重构代码都不许碰这一块。
- **代码标记格式**：
  ```javascript
  // @ANTIGRAVITY_INVARIANT_LOCK_START: 客户审阅系统法定特殊排版，严禁简化或重构
  // 核心受保护逻辑...
  // @ANTIGRAVITY_INVARIANT_LOCK_END
  ```

# 第二篇：16 个 Section 章节专属局部规范

这 16 个章节严格对应联合国 GHS 规范的标准 16 部分，每个章节都有其专属的业务特征和严苛排版细则。

---

### Section 1: 物料及供应商标识 (Identification)
- **通俗定位**：产品的“身份证”与厂家的“联络簿”。
- **专属核心规范**：
  1. **产品名称与型号绑定**：第一行首格必须准确填入产品型号（如 `PU-202B`），并与页眉右上角、页脚识别码、导出文件名四者实现 100% 同步联动。
  2. **主体信息法定替换**：
     - 若派生“冠志”版本：公司全称统一为 `广州冠志新材料科技有限公司`，地址、电话严格对齐冠志底模；
     - 若派生“国彩”版本：公司全称统一为 `英德市国彩新材料有限公司`，英文为 `Yingde Guocai New Material Co., Ltd.`，地址必须替换为广东省英德市东华镇清远华侨工业园，电话必须同步替换为国彩备案号码。
  3. **与 Section 16 独占性去重**：源文档中若把厂家地址、传真等信息散落写在第 16 节，系统必须将其提取归位至第 1 节，并在第 16 节剔除，杜绝重复出现。

---

### Section 2: 危险性概述 (Hazards Identification)
- **通俗定位**：告诉大家这个化学品有什么危险、怎么防范（骷髅头、感叹号、警告语）。
- **专属核心规范**：
  1. **GHS 象形图单元格保护**：
     - 如果产品有 GHS 危险类别，象形图必须保留黑边红菱形图片，且必须在单元格中完美居中；
     - 如果为非危险品，象形图单元格必须规范标注“无”或“Not applicable”，严禁出现图片破裂图标。
  2. **防范说明 P 码完整保全（严禁截断）**：
     - 必须完整提取安全防范说明，特别是末尾的 **`P405`（存放处须加锁）** 和 **`P501`（废弃物及容器处置）**，这是审阅批注的重点雷区，绝对不能遗漏丢失。
  3. **危险说明 H 码原子化对齐**：每个 H 编码（如 H315、H319）与警示语单独成行，不与非标散文混在一起。
  4. **第二节排版自动剪枝**：源文档中常见的“免责客套话”或多余的冗余说明段落，必须自动剪除，确保仅保留法定 GHS 分类条目。

---

### Section 3: 成分/组成信息 (Composition/Information on Ingredients)
- **通俗定位**：化学品的“配方表”（有哪些化学物质、CAS号是多少、占多少比例）。
- **专属核心规范**：
  1. **三列/四列表格文字必须居中**：
     - 表格中的“化学名称/组分”、“CAS 号”、“浓度范围（%）”各列内容，底层 XML 必须显式注入居中标记 `<w:jc w:val="center"/>`，保证打印时视觉整齐对齐。
  2. **CAS 编号精准对齐**：CAS 编号必须保持标准格式（如 `7732-18-5`），严禁拆散或换行截断。
  3. **浓度范围格式规范**：统一规范为 `20-30%`、`< 1%` 或 `35%` 格式，杜绝中英文混杂符号。
  4. **跨表混排解耦**：有些老旧源文档会把急救说明混排在成分表末尾，系统在提取时必须精准剥离，将急救文字自动流转到 Section 4，保持成分表纯粹。

---

### Section 4: 急救措施 (First-aid measures)
- **通俗定位**：万一吸入、吃到、溅到眼睛或皮肤上，该怎么急救。
- **专属核心规范**：
  1. **四维接触途径必须清晰分流**：
     - `吸入 (Inhalation)`：移至空气新鲜处，如有呼吸困难就医；
     - `皮肤接触 (Skin Contact)`：脱去污染衣物，用肥皂水和清水彻底冲洗；
     - `眼睛接触 (Eye Contact)`：用流动清水冲洗至少 15 分钟并就医；
     - `食入 (Ingestion)`：禁止催吐，漱口并立即就医。
  2. **禁止一大段散文堆砌**：四个维度必须分行或分槽位明确标注，标签加粗、说明常规，便于现场抢救人员 1 秒内抓取关键操作。

---

### Section 5: 消防措施 (Fire-fighting measures)
- **通俗定位**：万一着火了，用什么灭火器灭火、消防员要穿什么装备。
- **专属核心规范**：
  1. **灭火介质明确区分**：必须清晰区分“适用的灭火剂”（如泡沫、干粉、二氧化碳、水雾）与“不适用的灭火剂”（如高压水柱）。
  2. **特别危险性说明**：说明燃烧产生的有害气体（如一氧化碳、氮氧化物）。
  3. **消防人员专用装备**：明确消防员须佩戴自给正压式呼吸器（SCBA）并穿全身消防服。
  4. **英文章节标题保真**：英文版必须严格采用母版标题 `5.Fire fighting measures`。

---

### Section 6: 泄漏应急处理 (Accidental release measures)
- **通俗定位**：桶打翻了、水漏了，工人怎么防护、怎么围堵清理。
- **专属核心规范**：
  1. **三大处置维度闭环**：
     - 作业人员防护措施与应急程序（穿戴防护装备、切断泄漏源）；
     - 环境保护措施（防止泄漏物进入水体或下水道）；
     - 泄漏化学品的收容与清除方法（小量用砂土吸附，大量围堰转移）。
  2. **英文章节标题保真**：英文版必须严格使用官方母版标准标题 `6.Measures for accidental leakage`（严禁擅自改写为 Accidental release measures 而与模板脱节）。

---

### Section 7: 操作处置与储存 (Handling and storage)
- **通俗定位**：车间工人搬运时注意什么、仓库怎么放、温度多少度。
- **专属核心规范**：
  1. **安全操作注意事项**：密闭操作、局部排风、严禁进食与吸烟。
  2. **安全储存条件**：阴凉、干燥、通风良好；避免阳光直射；远离火种与热源；与强氧化剂分开存放。
  3. **防冻与温度要求**：对于水性聚氨酯等水性乳液产品，严格保留温度建议（如建议储存温度 5℃-35℃，严防受冻）。

---

### Section 8: 接触控制/个体防护 (Exposure controls/personal protection)
- **通俗定位**：车间空气中化学品浓度的安全红线，以及工人上班要戴什么口罩、手套、护目镜。
- **专属核心规范**：
  1. **建议行保全与前缀清洗**：如果源文档中有通风工程控制建议，完整保留；清洗多余的非标冗余前缀。
  2. **个体防护装备 (PPE) 四件套分流**：
     - `呼吸系统防护 (Respiratory Protection)`：空气中浓度超标时佩戴过滤式防毒面具或防尘口罩；
     - `眼睛防护 (Eye Protection)`：佩戴化学安全防护眼镜；
     - `身体防护 (Body Protection)`：穿防静电或防渗透工作服；
     - `手部防护 (Hand Protection)`：聚类并明确手套材质（如丁腈橡胶手套、氯丁橡胶手套）。
  3. **职业接触限值严谨性**：若有国家标准限值（PC-TWA / PC-STEL）如实填报；若无，规范填写“未制定标准”或“Not established”。

---

### Section 9: 理化特性 (Physical and chemical properties)
- **通俗定位**：化学品的“体检报告”（颜色、气味、pH值、沸点、闪点、粘度等）。这是全篇规则最密、要求最严的章节。
- **专属核心规范**：
  1. **法定 24 项槽位全保留（一个都不许删）**：
     - 无论源文件是否有数据，标准模板规定的全部 24 个理化槽位必须 100% 完整保留。
     - **缺失项填充规范**：源文档未提及的项目，必须规范填入统一表述：“无数据资料。”（中文版）或“Not applicable.” / “No data available.”（英文版），严禁留空或擅自把这行表格删掉。
  2. **消除 pH 标签叠词**：标签严格写作 `9.2  pH值：`，严禁出现 `pH值pH` 或 `pH pH值` 这类重复叠词错误。
  3. **专有理化指标测试条件解耦**：
     - 比如源文档写着“粘度 (25℃, mPa.s)：1500”，系统必须将测试条件 `(25℃)` 剥离出来，标签保持干净的 `9.20 粘度：`，而将条件 `25℃, 1500 mPa.s` 放入右侧填写值中。
     - 对 MFFT（最低成膜温度）、Tg（玻璃化转变温度）、羟值等树脂专属指标同理智能解耦。
  4. **Section 9 标签专属排版法定标准**：
     - **序号**：`Times New Roman`（或 Arial）`10.5pt` 加粗 + 尾随 **1 个标准英文半角空格**（如 `9.1 `）；
     - **标签文本**：`Arial` `12pt` 加粗（与母版 100% 对齐，杜绝黑体）；
     - **悬挂缩进**：严格为 `420 dxa`；
     - **零制表位**：底层绝对不允许出现破坏版面的 `<w:tabs>` 标签。

### Section 10: 稳定性和反应性 (Stability and reactivity)
- **通俗定位**：这个化学品脾气好不好（会不会爆炸、会不会自己坏掉、不能跟什么混在一起）。
- **专属核心规范**：
  1. **六大固定条目完整性**：
     - `反应性 (Reactivity)`：正常条件下无危险反应；
     - `化学稳定性 (Chemical Stability)`：在建议储存和操作条件下稳定；
     - `危险反应可能性 (Possibility of Hazardous Reactions)`：不会发生危险聚合；
     - `应避免的条件 (Conditions to Avoid)`：高温、强光、霜冻；
     - `不相容物质 (Incompatible Materials)`：强氧化剂、强酸、强碱；
     - `危险分解产物 (Hazardous Decomposition Products)`：正常条件下不分解，火灾时产生有害烟雾。

---

### Section 11: 毒理学信息 (Toxicological information)
- **通俗定位**：这个化学品有没有毒、会不会致癌、吃了或闻了会怎样。排版极其复杂，涉及网格自愈。
- **专属核心规范**：
  1. **实测数据提取第一优先级**：源文档中若有具体的急性毒性实验数据（如大鼠经口 LD50 > 5000 mg/kg），必须以源文档实测值优先提取填入，严禁被模板默认占位符覆盖。
  2. **急性毒性精准分流**：
     - 经口毒性、吸入毒性、经皮毒性必须精准分流至表格第二列对应的二级子标签槽位中，禁止将整段话一股脑覆盖到大标签所在行。
  3. **标签自适应清洗**：
     - 粘膜刺激性根据原文自适应改写为“主要粘膜刺激性”；
     - 致敏性试验清洗多余非标前缀；
     - 完整保留生殖毒性、特异性靶器官毒性（STOT）法定项目。
  4. **11.7 生殖毒性网格拓扑守恒与自愈（核心重点）**：
     - 原版模板中 11.7 为带“生育力”等子项的多列复合行，在收敛为标准单行时，中间列删除后，右侧值格必须自愈扩展为 `6262 dxa`，显式挂载 `gridSpan="3"`，并彻底清除残留悬空的 `vMerge` 属性，确保右边框绝对对齐。

---

### Section 12: 生态学信息 (Ecological information)
- **通俗定位**：流到河里或土里对鱼、水草、大自然有没有害。
- **专属核心规范**：
  1. **水生生物毒性分流**：鱼类、蚤类、藻类毒性数据清晰标注。
  2. **降解性与生物累积性**：如实列明持久性、降解性与生物富集潜能。
  3. **承接语与前言保全**：如果源文件在列出各成分生态毒理前有一句通用引导承接语（如“本产品对水生生物影响评估如下：”），必须完整保全，不能误当冗余删掉。

### Section 13: 废弃处置 (Disposal considerations)
- **通俗定位**：用完了剩下的废料、空桶怎么合规扔掉。
- **专属核心规范**：
  1. **处置原则法规依从**：明确建议将废弃物交由有资质的危险废物处理机构，依照当地环保法律法规进行处置或焚烧。
  2. **空包装容器管理**：空桶严禁随意丢弃或作生活使用，必须由专业单位回收或处置。
  3. **中英文结构完整**：英文版必须严格对齐双语结构，严禁段落断层缺失。

---

### Section 14: 运输信息 (Transport information)
- **通俗定位**：货车运、海运、空运该怎么申报（是不是危险品、UN编号是多少）。
- **专属核心规范**：
  1. **非危险货物级联判定**：
     - 若该产品不属于 GHS 危险品，必须在铁路、公路、海运、空运项下统一联动级联填报为：“非危险货物” / “Not regulated as dangerous goods”。
  2. **法定四大运输要素**：
     - `联合国危险货物编号 (UN Number)`：非危险品填“无”或“None”；
     - `联合国正确运输名称 (UN Proper Shipping Name)`：非危险品规范填写“未作规定”或“Not applicable”；
     - `包装类别 (Packing Group)`：若无填“无”；
     - `海洋污染物 (Marine Pollutant)`：明确标注“否 (No)”。

### Section 15: 法规信息 (Regulatory information)
- **通俗定位**：受哪些国家法律、法规监管。
- **专属核心规范**：
  1. **中国标准对齐 (CN 版)**：
     - 《中华人民共和国职业病防治法》
     - 《危险化学品安全管理条例》
     - 《安全生产许可证条例》

  2. **国际标准对齐 (EN 版)**：

  3. **列表聚合保全**：源文件列出的具体受控化学品名录，不得遗漏，完整聚合保全。

### Section 16: 其他信息 (Other information)
- **通俗定位**：免责声明、写表日期、参考书目、缩写词表。
- **专属核心规范**：
  1. **免责声明 (Disclaimer) 法定保全**：

# 第三篇：自查与审计速查口诀

在任何 MSDS 交付或提交审阅前，只需在心中快速过一遍这 **“六看六查”** 口诀：

```
一看封面八格式：双厂双语四双对（4 DOCX + 4 PDF，国彩冠志各两套）。
二查源件有备份：留存原件不能忘（_源文件留存.docx/pdf）。
三看英文无汉字：零字中文强门禁（正则扫描一个中文字都不许有）。
四查表格二元分：标签加粗值常规，三列居中四百二（420 dxa 悬挂，300 dxa 行距）。
五看九节二十四：项项齐全不删行，未测项填“无资料”（Section 9 全槽位保全）。
六查页眉与页脚：型号日期自动连，页码域留“3 / 5”（物理 XML 动态域代码）。
```

遵循以上规范，即可确保系统输出的每一套 MSDS 都能达到**法律合规无瑕疵、格式标准高保真、工业审阅免打回**的卓越标准！

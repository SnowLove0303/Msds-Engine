### 18. 值格零标签前缀叠词公理 (G-33 Anti-Stuttering-Prefix Invariant Axiom)
- **通俗解释**：表格左边如果已经写了标签名（比如“吸入：”、“致癌性：”），右边的值格里绝对不能一上来又重复一遍“吸入：”或“致癌性：”，否则在 Word 里看着就像结巴说话（“吸入：吸入：...”）。
- **底层法则**：
  - 流水线向所有值单元格（Value Cells）装配文本时，必须前置通过正则状态机物理剥离与当前标签或当前章节子标签完全重合的前缀字符串；
  - 严禁任何形式的标签-值文本粘连与重复叠词，审计套件对其执行零容忍硬断言。

### 19. 源文件实测化学端点零损耗保全公理 (G-34 Source Chemical Endpoints Zero-Loss Axiom)
- **通俗解释**：源文件里白纸黑字写出来的所有具体毒理学实验项目（比如经口、吸入、经皮，或者 1h/4h 多个测试浓度），一个字都不能丢！绝不能借口“模板只有两行”就把关键的经皮毒性或 4h 测试值随手删掉！
- **底层法则**：
  - 模板装配必须具备自适应插槽扩展能力，当单组分危化品源文件包含经口、吸入、经皮三大急性毒性数据时，表格行数自适应定格为 15 行，三大端点 100% 完整保留；
  - 英文版必须 1:1 双语同构对齐，严禁单边丢失。

### 20. 英文表格说明行均一正文字号公理 (G-35 English Table Preamble Typography Normalization Axiom)
- **通俗解释**：除 Section 2 外，英文版 MSDS 中凡属于说明行、前言行、免责通栏行，字号必须与英文表格标准填报值统一采用 9.5pt（底层 XML 对应 sz="19" 与 szCs="19"），严禁混入中文五号字 12pt（sz="24"）导致字体偏大 26.3% 的层级突兀感。
- **底层法则**：
  - **英文表格正文基准**：英文普通单元格标准字号为 9.5pt（sz="19"），中文表格标准字号为五号 12pt（sz="24"）；
  - **均一性与语义归属**：说明行与前言行在英文语义下属于 Value 内容流，字号必须统一收敛为 9.5pt Arial Regular；
  - **Section 2 绝对豁免（REQ-S2-EXEMPT）**：英文版 Section 2 属于 GHS 专有危险性分类排版，维持现状绝对豁免；
  - **中文版五号字保全（REQ-CN-PRESERVE）**：中文版说明行维持 12pt（sz="24"）宋体不变。

### 21. 交付物物理新鲜度与文件锁硬阻断公理 (G-36 Deliverables Freshness & File-Lock Hard-Blocker Axiom)
- **通俗解释**：绝对不允许“用户开着 PDF，流水线覆写失败却吞掉错误假装成功”！只要目标交付物被占用，重试失败必须立即抛出致命硬阻断异常（Exit Code 1），杜绝任何伪造成功与陈旧文件放行。
- **底层法则**：
  - **拒绝静默降级**：严禁将目标交付物降级写入 `(最新).pdf` 并随后由清理机制将其误删，严禁吞下 EBUSY 异常；
  - **物理时间戳新鲜度硬阻断 (G-Freshness)**：机械审计套件必须物理扫描 8 份交付物（4 DOCX + 4 PDF）的物理最后修改时间戳（mtime），8 个文件的生成时间差严禁超过 5 分钟，且必须严格处于本次构建时间窗口内，陈旧文件一票否决。

### 22. PDF 物理渲染字号终审双向硬断言公理 (G-37 PDF Physical Typography Dual-Audit Axiom)
- **通俗解释**：绝不能“只看 Word 里的 XML，不看最终给客户的 PDF”！必须由机械审计亲自用 Python PyMuPDF 穿透 PDF 文件，实测每一行文字在屏幕上真实的渲染像素与字号，所见即所审。
- **底层法则**：
  - **终审双极双向**：DOCX 底层 XML 断言与 PDF 实际渲染字号断言并重；
  - **PDF 9.5pt 硬指标**：英文版 Section 11、12、13 等说明行在 PDF 内的 span 实际字号必须严格在 9.4~9.6pt 之间，严禁残留 12.00pt。

# 第一篇：全局通用规范（全篇必须遵守的大原则）

这些规范是覆盖整份文档的“最高宪法”，无论在处理哪一个章节，都必须无条件服从。

### 1. 8 格式全套标准交付规范
- **通俗解释**：每做完一个产品型号的 MSDS，最后必须交付齐齐整整的 **8 个文件**（不多不少）。
- **具体清单**：
  1. `[型号] msds_CN 冠志.docx`（广州冠志 · 中文 Word）
  2. `[型号] msds_CN 冠志.pdf`（广州冠志 · 中文 PDF）
  3. `[型号] msds_EN 冠志.docx`（广州冠志 · 英文 Word）
  4. `[型号] msds_EN 冠志.pdf`（广州冠志 · 英文 PDF）
  5. `[型号] msds_CN 国彩.docx`（英德市国彩 · 中文 Word）
  6. `[型号] msds_CN 国彩.pdf`（英德市国彩 · 中文 PDF）
  7. `[型号] msds_EN 国彩.docx`（英德市国彩 · 英文 Word）
  8. `[型号] msds_EN 国彩.pdf`（英德市国彩 · 英文 PDF）
- **核心逻辑**：底层以两份官方标准母版（CN 冠志与 EN 冠志）为基准，通过“预设派生引擎”瞬间自动注入英德市国彩的主体信息（公司名、英文名、地址、电话、邮编），保证双主体、双语言全覆盖。

### 2. 源文件无损留存底线
- **通俗解释**：客户给的原始资料是无价凭据，严禁直接在客户原文件上盲改。
- **具体做法**：只要流水线或系统接收到客户的源文件（例如 `PU-202B msds_CN 冠志.docx`），在动工前系统必须自动复制一份命名为：
  - `[型号] msds_CN 冠志_源文件留存.docx`
  - `[型号] msds_CN 冠志_源文件留存.pdf`
- **目的**：不论后续发生任何意外、争议或审计复盘，永远有一份原汁原味的历史证据可供对质。

### 3. 英文版“零中文”强门禁
- **通俗解释**：给国外客户或外贸海关看的英文版 MSDS，全篇绝对不能漏掉任何一个中文字符（连一个中文标点都不行）。
- **检测机制**：
  - 导出英文交付物前，系统会自动扫描文档内的每一个字（基于中文字符正则 `[\u4e00-\u9fa5]`）。
  - **红线要求**：中文字符数必须严格为 **0**。只要发现残留（哪怕是源文档遗留的“广州”、“水性”或者中文逗号“，”），立刻触发熔断报错，禁止交付。

### 4. 表格排版“二元分类法则”（标签 vs 填写值）
- **通俗解释**：表格里的字不能想怎么排就怎么排，必须严格分成两类——**“标签”（Label）**与**“填写值”（Value）**，黑白分明。
- **具体排版特征对照**：
  | 项目 | 标签 (Label) | 填写值 (Value) |
  | :--- | :--- | :--- |
  | **字体加粗** | **必须加粗**（底层 XML 注入 `<w:b/>`） | **绝对不加粗**（必须剥除 `<w:b/>`） |
  | **字体族与大小** | `Arial` 字体，五号字（`12pt` / `24 half-points`） | `Arial` 字体，五号字（`12pt` / `24 half-points`） |
  | **固定行距** | 严格为 `300 dxa`（保证 Word 视觉紧凑专业） | 严格为 `300 dxa` |
  | **缩进与对齐** | 多行复合标签挂载 `420 dxa` 悬挂缩进 | 顶格对齐，无悬挂缩进 |
  | **制表符禁令** | **严禁手写插入 `<w:tabs>` 制表位**（杜绝制表符飞格） | 严禁多余制表符 |

### 5. 表格几何拓扑守恒与自愈中枢 (normalizeRowGeometry)
- **通俗解释**：删掉表格里的某一列后，整个表格不能“塌方”或者右边凹进去一块（像缺了个角一样难看）。
- **核心规矩**：
  - 无论在哪个章节（特别是 Section 11 的 11.7 生殖毒性等多列复杂行），当把原本的“三列/多列”合并收敛为“双列”时，**表格总宽度必须绝对守恒（如 9781 dxa）**。
  - **自愈动作**：删掉中间列后，系统底层自动将右侧的值单元格宽度扩展补齐至 `6262 dxa`，并显式注入跨列标记 `<w:gridSpan w:val="3"/>`，同时**强制剥除残留的悬空 `<w:vMerge>`（纵向合并）标记**，保证右边框 100% 垂直齐平。

### 6. 跨页排版断行全开保护
- **通俗解释**：当表格很长、一页纸装不下的时候，允许表格在两页之间自然分页，不能死板地强制整行表格硬生生挤到下一页导致上一页留下巨大的刺眼大空白。
- **底层规矩**：系统在载入和导出模板时，会全局巡检并彻底清除所有单元格和表格上的禁止分页属性（如 `<w:cantSplit/>`），让长文本和多行数据平滑跨页。

### 7. 全局页眉页脚与物理 XML 注入
- **通俗解释**：页眉页脚不是在正文画画，必须真真切切写入 Word 底层的 `header1.xml` 和 `footer1.xml` 里，打印每一页都有。
- **版式规则**：
  - **页眉 (Header)**：左侧为主标题（`物料安全数据表` / `MATERIAL SAFETY DATA SHEET`）及版本号（`Version: V1.0`）；右上角第一格为加粗的产品型号（如 `PEA-4139`）。
  - **页脚 (Footer)**：
    - 公司名称严格靠左对齐（`<w:jc w:val="left"/>`）；
    - 中间/右侧自适应呈现系统当前最新修订日期（如 `2026年10月08日`）；
    - **页码保护**：完整保护保留 Word 原生的动态域代码（`PAGE` 与 `NUMPAGES`），即显示为 `3 / 5`，绝不能被写死为静态数字。

### 8. 模板防污染与安全清空协议 (Clean Slate)
- **通俗解释**：模板里本来可能印着样例数据（比如参考型号 `PEA-4139` 或示例文字），往里面填新产品数据前，必须把这些示例文字彻底洗干净，绝不能把老数据留下来混在新数据里（“零数据残留”）。
- **底层规矩**：系统执行智能装配前，启动安全清零协议：只保留模板的表格骨架、标题和固定标签，将所有值格（Value Cells）清空，源文档没有提到的项坚决不瞎编（“零臆造”）。

### 9. 前置双清单确认门禁与 VS Code 两栏比对检阅
- **通俗解释**：Agent 或系统改动代码前，必须先列清单向人工请示；改完之后，人工必须在 VS Code 原生双栏比对窗口里审阅过，按确定才算数。
- **双清单制**：
  1. **清单 1（拟变更范围）**：改动哪些文件、涉及什么函数、怎么验证；
  2. **清单 2（保持现状承诺）**：向用户明确保证绝不触碰、绝不删改原有的哪些正常业务逻辑。

### 10. 代码级防篡改封印标记机制 (@ANTIGRAVITY_INVARIANT_LOCK)
- **通俗解释**：对于经过反复调试确认的极其核心的特殊业务代码，打上“封印”标记，任何人或 Agent 来重构代码都不许碰这一块。
- **代码标记格式**：
  ```javascript
  // @ANTIGRAVITY_INVARIANT_LOCK_START: 客户审阅系统法定特殊排版，严禁简化或重构
  // 核心受保护逻辑...
  // @ANTIGRAVITY_INVARIANT_LOCK_END
  ```

### 11. 中英文双语结构拓扑同构公理 (Bilingual Structural Isomorphism Axiom)
- **通俗解释**：中文版怎么排，英文版就必须一模一样怎么排。如果中文版是 4 行、第 4 行拆成 4 个独立段落，英文版绝对不能自作主张缩水成 1 行或合并成 1 个大长段落！
- **底层规矩**：表格的行数（Row）、单元格数（Cell）、通栏单元格内的段落数（Paragraph）必须 1:1 精确映射，中英文结构绝无断层。

### 12. 标点完整性与语义分层闭合公理 (Punctuation Integrity & Semantic Closure Axiom)
- **通俗解释**：完整成句的陈述叙述，结尾必须有句号（中文 `。`, 英文 `.`）；严禁在句子末尾留下没写完的悬空冒号（`:` / `：`）、分号（`;` / `；`）或逗号；但对于名词性状态短语声明（如“刺激性：无资料”），严格保留手做母版原貌，末尾不画蛇添足加句号。
- **底层规矩**：
  1. 叙述性完整句子末尾必须以句号闭合（如 Section 4 急救“若发生皮肤反应，就医。”、Section 5 灭火“大火时应用喷洒水。”、Section 7 操作“更换被污染或浸湿的衣物。”）；
  2. 名词性状态声明短语（如 Section 11 中文各组分末尾“刺激性：无资料”）保持手做母版无句号规范；
  3. 英文冒号后严格留 1 个半角空格（如 `Toxicity: `）；中文冒号后不得有多余空格；
  4. 审计与校验必须使用感知软换行符 `<w:br/>` 的解析器（如 `getPText`），换行分行的指标不判定为文本粘连。

### 13. 冒号间距公理 (Colon Spacing Invariant Axiom)
- **通俗解释**：中文标点自带字距，冒号后严禁敲空格；英文西文标点没有字距，冒号后必须且只能留 1 个标准空格。
- **底层规矩**：中文冒号后空格数严格为 0；英文半角冒号后空格数严格为 1。

### 14. 反多空格排版与法定列对齐缩进公理 (Anti-Multi-Space & Column Alignment Axiom)
- **通俗解释**：严禁在正文中使用无序连续空格随意排版；但在多行通栏等特殊排版场景中，为对齐首行 3 个中文字符的前置标签（如 `毒性：`），后续行行首必须允许使用**严格 6 个半角空格**（中文版）或 **10 个半角空格**（英文版对齐 `Toxicity: `）作为法定列对齐缩进。
- **底层规矩**：
  1. **法定首列对齐白名单**：Section 11 等多成分通栏复合单元格中，换行指标行首允许且必须包含中文版严格 6 空格对齐 3 汉字标签；英文版指标行首包含严格 8 空格使 `Inhalation` 与 `Oral` 垂直对齐 `Dermal`，并在各端点后注入 3/5 空格使全部 `LD50:` 标签垂直绝对一字排开齐平；组分之间以空行（软回车）隔离；
  2. **正文严禁乱敲多空格**：除上述法定列对齐空格外，正文文本严禁出现任意 `/[ ]{2,}/` 乱排版。

### 15. 值格字体分离与显式常规体公理 (Font Weight Separation & Explicit Regular Axiom)
- **通俗解释**：表格里的组分大标题可以加粗，但具体子标签和数值测试结论绝不允许全篇一片黑（严禁整个单元格全加粗）；同时在 Word 底层，显式带有 `<w:b w:val="0"/>` 的是正规的“取消加粗/常规体”，绝对不能被误判为加粗。
- **底层规矩**：
  1. Section 11 顶部免责说明行（Row 1）与成分引言行（Row 2）严格保持常规体（`bold: false`）；
  2. 通栏单元格中仅组分大标题加粗（如 `丙二醇丁醚：`），子标签（`毒性：`、`刺激性：`）与测试值必须保持常规体（Regular）；
  3. 中文版 Section 11 的 `ascii`、`hAnsi`、`eastAsia` 字体必须三轴统一锁定为 `宋体`。

### 16. 全流程双极双层深度审计强制门禁 (Bipolar Bilayer Panoramic Deep Audit Mandate)
- **通俗解释**：所有型号生成出来的所有交付物，在交付前必须经过一次真正的“深度扫描”。不能只查关键词有无，必须逐行检查段落数、软换行、标点闭合、缩进、加粗状态机。

### 24. OPC 包与 [Content_Types].xml 媒体声明完备性公理 (G-39 Open Packaging Conventions Fidelity Axiom)

- **底层规矩**：

### Section 9: 理化特性 (Physical and chemical properties)
- **通俗定位**：化学品的“体检报告”（颜色、气味、pH值、沸点、闪点、粘度等）。这是全篇规则最密、要求最严的章节。

  2. **消除 pH 标签叠词**：标签严格写作 `9.2  pH值：`，严禁出现 `pH值pH` 或 `pH pH值` 这类重复叠词错误。
  3. **专有理化指标测试条件解耦**：
     - 比如源文档写着“粘度 (25℃, mPa.s)：1500”，系统必须将测试条件 `(25℃)` 剥离出来，标签保持干净的 `9.20 粘度：`，而将条件 `25℃, 1500 mPa.s` 放入右侧填写值中。
     - 对 MFFT（最低成膜温度）、Tg（玻璃化转变温度）、羟值等树脂专属指标同理智能解耦。
  4. **Section 9 标签专属排版法定标准**：
     - **序号**：`Times New Roman`（或 Arial）`10.5pt` 加粗 + 尾随 **1 个标准英文半角空格**（如 `9.1 `）；
     - **标签文本**：`Arial` `12pt` 加粗（与母版 100% 对齐，杜绝黑体）；
     - **悬挂缩进**：严格为 `420 dxa`；
     - **零制表位**：底层绝对不允许出现破坏版面的 `<w:tabs>` 标签。

### Section 10: 稳定性和反应性 (Stability and reactivity)
- **通俗定位**：这个化学品脾气好不好（会不会爆炸、会不会自己坏掉、不能跟什么混在一起）。
- **专属核心规范**：
  1. **六大固定条目完整性**：
     - `反应性 (Reactivity)`：正常条件下无危险反应；
     - `化学稳定性 (Chemical Stability)`：在建议储存和操作条件下稳定；
     - `危险反应可能性 (Possibility of Hazardous Reactions)`：不会发生危险聚合；
     - `应避免的条件 (Conditions to Avoid)`：高温、强光、霜冻；
     - `不相容物质 (Incompatible Materials)`：强氧化剂、强酸、强碱；
     - `危险分解产物 (Hazardous Decomposition Products)`：正常条件下不分解，火灾时产生有害烟雾。

### Section 11: 毒理学信息 (Toxicological information)
- **通俗定位**：这个化学品有没有毒、会不会致癌、吃了或闻了会怎样。排版极其复杂，涉及网格自愈。
- **专属核心规范**：
  1. **实测数据提取第一优先级**：源文档中若有具体的急性毒性实验数据（如大鼠经口 LD50 > 5000 mg/kg），必须以源文档实测值优先提取填入，严禁被模板默认占位符覆盖。
  2. **急性毒性精准分流**：
     - 经口毒性、吸入毒性、经皮毒性必须精准分流至表格第二列对应的二级子标签槽位中，禁止将整段话一股脑覆盖到大标签所在行。
  3. **标签自适应清洗**：
     - 粘膜刺激性根据原文自适应改写为“主要粘膜刺激性”；
     - 致敏性试验清洗多余非标前缀；
     - 完整保留生殖毒性、特异性靶器官毒性（STOT）法定项目。
  4. **11.7 生殖毒性网格拓扑守恒与自愈（核心重点）**：
     - 原版模板中 11.7 为带“生育力”等子项的多列复合行，在收敛为标准单行时，中间列删除后，右侧值格必须自愈扩展为 `6262 dxa`，显式挂载 `gridSpan="3"`，并彻底清除残留悬空的 `vMerge` 属性，确保右边框绝对对齐。
  5. **Section 11 双范式动态路由与三级责任隔离通栏排版准则 (单空行 before="240" 与多指标垂向对齐)**：
     - **双范式动态路由**：当检测到包含 $\ge 2$ 种独立化学组分的毒理学试验数据时，自动触发范式 1（通栏模式）；仅含 1 种组分或未拆解数据时，严格遵循范式 2（模板原装 18 行标准双列槽位模式）。
     - **单组分危化品原版分列表格 15 行同构与三项必齐准则 (L-S11.1)**：
       - 当源文档为单组分危险品（如 PU-202A 仅含 DMAC）时，严格遵循原版分列表格（中英双语严格 15 行 1:1 对齐）；
       - 急性毒性必须完整保留三大端点：① 经口（Oral）；② 吸入（Inhalation，完整保留 1h 与 4h 两个测试浓度事实）；③ 经皮（Dermal，如豚鼠 <940mg/kg），绝不允许丢失经皮行；
       - 11.2 标签术语严格遵从源文件法律事实（若源文件为“主要皮肤刺激性:”，严禁被篡改为“原发性皮肤刺激:”）；
       - 11.4 致敏性与 11.10 附加信息保留多测试项换行独立分段展示；
       - 值单元格（Value Cells）全篇全为常规体（Regular，加粗数严格为 0），中文宋体五号 12pt（24 twips），英文 Arial 9.5pt（19 twips）。
        - 英文版说明行统一 9.5pt（G-35 / L-S11-EN）：Row 1（产品免责说明行）与 Row 2（前言说明行）在英文版中底层 XML sz 与 szCs 严格为 "19"（9.5pt Arial Regular），与表格值保持绝对一致，中文版维持 "24"（12pt 宋体）。
     - **三级责任隔离 4 行拓扑**：
       - Row 0：章节标题（`11. 毒理学信息`）；
       - Row 1（Level 1 产品级免责通栏，`gridSpan="3"`，`w="9781"`）：`该产品无可用的毒理学研究。`（常规体，`jc="left"`）；
       - Row 2（Level 2 原料前言通栏，`gridSpan="3"`，`w="9781"`）：`下面是这些成分的毒理学数据。`（常规体，`jc="left"`，微缩进 `w:left="34"`）；
       - Row 3（Level 3 组分实测毒理通栏，`gridSpan="3"`，`w="9781"`）：各组分实测数据（仅组分标题加粗，试验数据正文全常规体）。
     - **组分间距严格单空行公理**：每个组分段落首行使用 `<w:spacing w:before="240"/>`（12pt / 1倍行高）精确隔离，严禁使用前置 `\n` 或软回车 `<w:br/>` 造成物理空两行；
     - **多指标垂向对齐**：经皮、吸入、经口的测试指标（LD50/LC50）在冒号与数值处垂向一字排开对齐，英文冒号后严格保留 1 个半角空格。

### Section 12: 生态学信息 (Ecological information)
- **通俗定位**：流到河里或土里对鱼、水草、大自然有没有害。
- **专属核心规范**：
  1. **水生生物毒性分流**：鱼类、蚤类、藻类毒性数据清晰标注。
  2. **降解性与生物累积性**：如实列明持久性、降解性与生物富集潜能。
  3. **承接语与前言保全**：如果源文件在列出各成分生态毒理前有一句通用引导承接语（如“本产品对水生生物影响评估如下：”），必须完整保全，不能误当冗余删掉。

- **通俗定位**：用完了剩下的废料、空桶怎么合规扔掉。

### Section 14: 运输信息 (Transport information)
- **通俗定位**：货车运、海运、空运该怎么申报（是不是危险品、UN编号是多少）。
- **专属核心规范**：

  2. **法定四大运输要素**：
     - `联合国危险货物编号 (UN Number)`：非危险品填“无”或“None”；
     - `联合国正确运输名称 (UN Proper Shipping Name)`：非危险品规范填写“未作规定”或“Not applicable”；
     - `包装类别 (Packing Group)`：若无填“无”；
     - `海洋污染物 (Marine Pollutant)`：明确标注“否 (No)”。

# 第三篇：自查与审计速查口诀

在任何 MSDS 交付或提交审阅前，只需在心中快速过一遍这 **“八看八查”** 口诀：

```
一看封面八格式：双厂双语四双对（4 DOCX + 4 PDF，国彩冠志各两套）。
二查源件有备份：留存原件不能忘（_源文件留存.docx/pdf）。
三看英文无汉字：零字中文强门禁（逐个文本节点筛查，一个汉字都不许有）。
四查表格二元分：标签加粗值常规，三列居中四百二（420 dxa 悬挂，数值严禁全黑）。
五看九节二十四：项项齐全不删行，未测项填“无资料”（Section 9 全槽位保全）。
六查页眉与页脚：型号日期自动连，页码域留“3 / 5”（物理 XML 动态域代码）。
七审标点与空格：悬空冒号不可留，完整句子句号收，严禁多空格充对齐。
八验双语同构性：段落行数一对一，通栏结构零缩水，双极双层深度查。
```

遵循以上规范，即可确保系统输出的每一套 MSDS 都能达到**法律合规无瑕疵、格式标准高保真、工业审阅免打回**的卓越标准！

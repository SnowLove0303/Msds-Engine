# MSDS Studio 覆写问题汇总与 Agent 快调系统需求报告

> 范围：PU-2341E（V2）＋ PA-3617 两次经 Web 编辑器引擎覆写的全过程复盘。
> 结论先行：覆写本身能跑通，但今天的链路是“手工作坊”——靠一次性脚本、手工 dump、LibreOffice 渲染探针粘起来的。
> 目标：建成 Agent 五步快调系统——导入 → 系统识别内容 → Agent 分类内容 → 调用编辑功能编辑 → 调用导出功能导出 → 交付，
> 全程标准化 API 调用，无渲染、无探针、无手工取证。

## 一、你的需求我理解如下（先对齐，不对你直接打回）

1. **调用者是 Agent，不是人**：不需要打开页面点按钮，要的是程序接口（函数/CLI/HTTP 任一稳定形态），传参进去、拿文件出来。
2. **五步固定**：导入 → 系统识别内容 → Agent 分类内容 → 调用编辑功能编辑 → 调用导出功能导出 → 交付。每步输入输出定死，不许 Agent 自由发挥、不许加戏。
3. **快**：渲染、手工 dump、探针 docx、逐页目检这些是我研发期取证用的“乱七八糟”，生产流程里一律没有。慢的根因（返工）用门禁前置消灭，而不是用渲染事后发现。
4. **标准化**：同一套约束、同一套映射表结构、同一套审计门，换哪个产品、换谁来调，结果一致。

## 二、覆写过程中遇到的问题清单（按阶段）

### 阶段 A：导入识别

- A1：源表是单列合并布局时（如 PA-3617 S8/S11），值藏在 label 侧或无槽位划分，取值函数必须带回退（valueText → labelText → text），否则取空还不报错。
- A2：Word 自动编号（7.1 类）不在文本里，只在 numPr 里；只看 cell.text 会丢号。引擎侧已解决（normalizedSequence），但 Agent 若绕过引擎自读就会踩。
- A3：识别结果无“动作”概念——只告诉你有什厶，不告诉你删不删、往哪贴，Agent 只能手写映射，容易把 8.1 写进 8.2 这类反直觉槽搞错（V2 实踩：8.2 写空）。

### 阶段 B：分类映射（问题最密的阶段）

- B1：**没有映射表机制**：源槽→模板槽＋动作（MAP/删/改）全靠一次性脚本硬编码，换个产品重写一遍，错一次返工一轮。
- B2：S2 无源行必须整行删（PA-3617 删 13 行），但“删哪些”靠人数，缺一张 S2 槽位清单。
- B3：S9 按名匹配会串行（“密度”命中“相对蒸气密度”，实踩，已改行号锚定＋断言），说明按名匹配不可靠，必须行号/槽位锚定。
- B4：S9 新增行（MFFT/Tg）克隆后序号与邻行重复，引擎重排不会修（复用 11.1 重号逻辑），被迫打 DOM 补丁——这是引擎缺“S9 插入”专用 writer 的证据。
- B5：S11 无源端点（11.6–11.10）删 7 行，删后须保规范端点号；引擎重排在这里是恒等操作，靠对不靠验。

### 阶段 C：编辑写入（引擎 API 层面）

- C1：**空值格不可写**（S8“建议”模板值格为空，`editable=false`，写即抛 LOCKED_FIELD）——源有值也进不去，只能跳过上报。这是当前最大内容 fidelity 缺口。
- C2：**页眉页脚写了也白写**：`exportArrayBuffer` 只回写 `document.xml`，header/footer 改动必然丢失，且题头格不可编辑。PEA-4139 题头/页脚盖不上，属实锤引擎限制。
- C3：`writeCellLabel` 只保前缀不改号，新增 S9 行定号必须另想办法（见 B4）。
- C4：`addRow/deleteRow` 自带重排是好事，但 S9/S11 场景下语义不对，需要调用方二次修正——API 缺“重排策略”参数。
- C5：多行值 `\n` 转 `w:br` 单段落是对的（S5/S6/S13 渲染验证通过），这条是刻意保留的正确行为。

### 阶段 D：审计导出

- D1：`auditEngine` 只覆盖序号连续与基础结构，不查示例残留、空标签行、字体、身份、跨表一致——V2 的 PEA-4139 和空 8.2 它全放行。生产门禁必须另起一层。
- D2：导出即出包，无构建日期戳、无证据包（映射表/追溯/AGENT_DECISION），交付后无法复盘。

### 阶段 E：模板原生问题（非引擎之过，但每次都撞）

- E1：S8 手部行标签夹带呼吸文字（笔误，Q-2 待裁决）。
- E2：S7R1/S11R1 在 LibreOffice 渲染不可见，数据层三重验证正确，模板自己也一样——属渲染 quirks，终签以 Word/WPS 原生为准。
- E3：模板 S9 缺 9.23、S11 11.7 三空子行、S15 单列结构，映射时须特判。

### 附：我用的“乱七八糟”（研发取证，生产流程删除）

python dump、tpl_structure 转储、LibreOffice 全页渲染、S7 探针 docx×2、行级 XML diff——这些是为了定责（数据层 vs 渲染层 vs 模板层）一次性取证，**快调系统里一个不留**，对应能力全部收进门禁断言。

## 三、快调系统方案（五步，每步定输入输出）

- 第 1 步 导入：`import(docx) → docId`，源文件只读登记。目标 <5 秒。
- 第 2 步 系统识别内容：`recognize(docId) → 16节JSON（标签/值/合并格/编号/字体角色）`。目标 <30 秒。无动作建议，只给事实。
- 第 3 步 Agent 分类内容：Agent 输出**映射表**（源槽→模板槽＋五动作），系统校验（槽位存在性、动作合法性、S2/S8/S11 必映射项齐全），不过即停。目标 <60 秒校验。
- 第 4 步 调用编辑功能编辑：`overwrite(templateId, mapping) → workDoc`，只允许写值/增删行/重排三类调用，逐项回读断言，异常即停即报行号。目标 <120 秒。
- 第 5 步 调用导出功能导出＋交付：先跑生产门禁（残留/空行/编号/字体/身份/一致性），全绿出包＋证据包＋交付清单。目标 <60 秒。
- 全程无渲染；渲染仅保留为调试开关（`--render-debug`），默认关闭。

## 四、缺口清单（按依赖排序，做完即达标）

1. 映射表 schema＋校验器（含 S2/S8/S11 必映射项）。—— 没有它，B1/B2/B3 重演。
2. hardened 编辑 API：空槽写入（解 C1）、S9 插入定号 writer（解 B4/C3）、重排策略参数（解 C4）。
3. 页眉页脚导出回写（解 C2），或模板去示例化二选一，需你拍板。
4. 生产门禁层（解 D1）＋证据包（解 D2）。
5. Q-1（S9 9.2 限定词）、Q-2（S8 笔误）裁决——不裁，S8/S9 逻辑写不死。
6. CLI/HTTP 壳＋wll 接入（已有 MSDS Studio 启动项，覆写是一句话的事）。

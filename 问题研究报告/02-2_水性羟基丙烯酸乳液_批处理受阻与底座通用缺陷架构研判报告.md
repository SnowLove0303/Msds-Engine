## 四、 针对前缀叠词（`.18 羟基含量:`）的技术深潜

在现场证据 2 中，英文交付物中出现了前缀叠词：
```xml
<w:r><w:t>9.18</w:t></w:r>
<w:r><w:tab/></w:r>
<w:r><w:t>.18 羟基含量:</w:t></w:r>
```

### 叠词根因与解毒逻辑：
1. **产生根因**：源文件中的原始文本为 `9.18羟基含量`。当掉入 `else { enLabel = cnLabel }` 兜底分支时，`cnLabel` 未被清理，直接带入标签写入逻辑，与系统自动注入的法定序号 `9.18` + `<w:tab/>` 发生局部碰撞，产生残余 `.18`；
2. **解毒机制**：当 `translateSection9Item` 正确命中 `/羟基含量/i` 后，函数显式返回纯净的规范英文标签 `enLabel = 'Hydroxyl content:'`；
3. **输出效果**：底层 OOXML 将精准生成：
   - Run 1 (序号加粗): `9.18`
   - Run 2 (制表符): `<w:tab/>`
   - Run 3 (英文标签 Arial 9.5pt 加粗): `Hydroxyl content:`
   - Run 4 (纯净数值): `1.0`
4. **结论**：叠词现象在规范化英译生效后将彻底自然消除，无需在排版引擎中做脆弱的字符串裁剪。

## 1. 排查结论

模板编辑器打不开的直接原因是 **main.js 使用了 TEMPLATE_BASELINES，却没有从 docx-engine.js 导入它，浏览器执行时发生 ReferenceError。**

docx-engine.js 已经正确导出模板基准数组；缺失发生在使用方的 import 列表。

因此，点击模板编辑器后，内部视图状态虽然发生切换，但生成编辑器 HTML 时抛出异常，页面没有完成 DOM 更新，用户仍看到原来的识别页，表现为“按钮点了没有反应”“模板编辑器无法打开”。

此次故障已在独立浏览器上下文复现。临时为该隔离页面补齐同名运行时变量后，模板编辑器可以正常呈现，出现两个模板基准选项及编辑内容区域；删除临时变量并刷新后，初始化错误再次出现。这一对照验证直接支持漏导入是当前入口阻断原因。

5173 端口服务、主页面、JavaScript 资源和两份 DOCX 模板均可访问。现有证据不支持将本次故障归因为 Docker、服务未启动、中文模板丢失或单纯的浏览器旧缓存。


这说明模板基准数据并没有缺失。问题是 main.js 没有建立模块导入绑定。

### 4.2 使用方 import 列表漏了一项

[main.js 文件开头](<F:/App Location/Guanzhi Tong/Skill/MSDS-Engine/web/src/main.js:2>) 的 docx-engine.js 导入末尾包含：

```js
  extractSemanticSnapshot,
  applySemanticOverrides,
  SYSTEM_BUILTIN_PRESETS,
} from './docx-engine.js';
```

其中没有 TEMPLATE_BASELINES，文件内也没有本地定义。

### 4.3 新增流程多次使用未绑定变量

| 位置 | 使用方式 | 影响 |
|---|---|---|
| main.js:473 | getCurrentBaseline 中查找注册项 | 获取当前基准可能失败 |
| main.js:521 | switchBaselineDraft 中查找目标基准 | 初始加载/基准切换失败 |
| main.js:578 | renderBaselineSelectorMarkup 中遍历基准 | 模板编辑器渲染直接失败 |
| main.js:664、761、820 | 导出准备/列表中遍历基准 | 关联导出流程也存在同源阻断 |
| main.js:935 | 预设管理按基准分组 | 关联管理流程也存在同源阻断 |
| main.js:3878 | fetchTemplate 的基准名称解析 | 非旧映射名称的加载受影响 |

本次实际复现的是入口渲染和初始化错误；未逐一触发所有关联管理/导出功能。

### 4.4 为什么旧识别页仍然显示

导航事件在 main.js 第 2261 行附近先设置 state.view，再调用 renderApp：

```js
state.view = button.dataset.view;
// ...
renderApp();
```

renderApp 先计算当前页面内容：

```js
if (state.view === 'inspect') content = renderInspector();
else if (state.view === 'matching') content = renderMatching();
else content = renderEditor();

// 完成上面的内容计算后才更新 root.innerHTML
```

renderEditor 在生成模板基准选择器时抛错，执行到不了后面的 root.innerHTML 赋值，旧 DOM 留在页面上。

因此，这不是导航按钮根本没有绑定点击事件。实际是点击已触发，但后续渲染失败且缺少用户可见的错误状态。

### 4.5 初始化 fallback 无法解决同一个渲染错误

bootstrap 先调用 switchBaselineDraft，失败后退回 loadEditorTemplate('CN 冠志')。后者能读到中文模板，却仍会进入同一个编辑器渲染链路，继续遇到缺失的 TEMPLATE_BASELINES。

回退逻辑覆盖了“模板加载路径”，没有覆盖“渲染依赖缺失”；不能靠再加载一次中文模板恢复页面。

## 7. 应同时完善的错误反馈

这些属于建议后续改进，与最小修复分开实施：

1. 导航异步事件捕获错误，提示失败位置；失败时恢复原导航状态或展示明确错误页，不让内部状态与可见页面脱节。
2. 编辑器渲染错误提供可见提示，避免只留下控制台报错和未变的旧页面。
3. 初始化错误区分“资源加载失败”和“界面运行异常”，不要吞掉后者后继续回退。
4. 模块依赖在应用入口加入 no-undef 检查，避免具名导出已存在但使用方忘记 import。
5. 基准切换失败时保留原稿、原基准 ID 与 UI 状态，不应提前提交目标状态后直接吞错。

第 5 项是源码中可见的相邻风险：switchBaselineDraft 在完成目标资源加载前已经更新 currentBaselineId。本次没有用用户稿件测试失败切换，不将其写为已经造成数据丢失。

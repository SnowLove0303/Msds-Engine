## 二、 OS-8503DMM 覆写期全量问题穿透与根因清算

`OS-8503DMM` 是水性聚碳化二亚胺交联剂领域的特殊化学品（含有 50% 二丙二醇二甲醚 DMM 有机溶剂）。在覆写与初审过程中，暴露出多项严重的认知偏差与排版退化问题：

### 2.1 Section 1 中文名称被大类名称污染与覆写位置倒置
- **问题现象**：  
  初审 Agent 指控交付物中文版 Row 2 `中文名称：` 留空属于严重缺陷。但随后发现，若将型号写入 Row 1 `1.1 产品名称：`，会导致题头污染；若将型号直接当做产品名，又丢失了化学大类品名。
- **5-Whys 根因穿透**：
  - *Why 1?* Agent 不熟悉企业特定的《局部覆写规范 (OW-080)》。
  - *Why 2?* 公司模板将 `1.1 产品名称：` 设计为大类父级题头，按公司惯例其值单元格必须严格留空，杜绝写入任何内容。
  - *Why 3?* 真实的产品品名与型号组合（`中文产品名 + 1 半角空格 + 型号`）法定归口在 Row 2 `中文名称：`。
- **归正对策**：  
  清空 Row 1 值单元格；在 Row 2 值单元格精确写入 `碳化二亚胺交联剂 OS-8503DMM`，Row 3 补齐化学品分类 `聚碳化二亚胺`。

### 2.2 Section 1 英文版化学事实失真与末尾标点污染
- **问题现象**：  
  英文版交付物中，产品名称被写为带句号的 `Waterborne Polycarbodiimide Crosslinker OS-8503DMM.`，且分类被误标为 `Aqueous polymer dispersion.`。
- **5-Whys 根因穿透**：
  - *Why 1?* 模板自带的默认占位符属于丙烯酸/环氧乳液的水分散体，未根据溶剂型碳化二亚胺事实更新。
  - *Why 2?* 翻译引擎无脑给所有单行文本追加了英文句号（`.`），破坏了标题不带句号的国际排版惯例。
- **归正对策**：  
  英文 Row 1 剔除末尾句号；Row 2 分类修正为真实的化学实体 `Polycarbodiimide`，彻底消灭“高分子水分散体”幻视。

### 2.3 Section 8 职业接触限值实测数据行整行丢失
- **问题现象**：  
  产出物中 Section 8 只有表头（成分、标准、类型、限值），原本源文件中明确载明的接触限值数据行消失无踪，仅剩下空表格。
- **5-Whys 根因穿透**：
  - *Why 1?* 历史匹配逻辑在处理溶剂组分时，因 DMM 属于有机溶剂且有特定限值，未能准确映射至 OEL 槽位。
  - *Why 2?* 粗暴的剪枝策略将“未能完美命中通用字典”的数据行直接丢弃。
- **归正对策**：  
  精准补全 Row 14 职业接触限值实测数据行：
  - 中文版：`丙二醇甲醚醋酸酯 | CN OEL | TWA | 100 mg/m3`；
  - 英文版：`Propylene glycol methyl ether acetate | CN OEL | TWA | 100 mg/m3`。

### 2.4 Section 8 手套参数缺失与 Recommendation 缩进锯齿
- **问题现象**：  
  中文版与英文版中，防护手套材质、厚度与渗透时间丢失；英文版中的 `Recommendation:` 标签靠左顶格，与上下其他 PPE 标签产生严重锯齿状视觉凹凸。
- **5-Whys 根因穿透**：
  - *Why 1?* PPE 标签缩进未统一绑定到 `left="420"` (21pt / 1字符) 标尺。
  - *Why 2?* `docx-engine.js` 在渲染英文 Recommendation 时，未剥离 `firstLine` 导致缩进坍塌。
- **归正对策**：  
  强制补全 FKM (0.4 mm, 480 min)、IIR (0.5 mm, 480 min)、NBR (0.35 mm, 480 min) 完整参数，并对 Recommendation 施加 `w:left="420"`，实现垂直共线对齐。

### 2.5 Section 9 闭口闪点 65℃ 关键安全事实丢失与外观失真
- **问题现象**：  
  英文版 Section 9 闭口闪点变成 `No data available.`，且外观颜色由“黄色透明液体”退化为无色。
- **5-Whys 根因穿透**：
  - *Why 1?* 闭口闪点 65℃ 是支撑 Section 2 易燃液体 Cat 4 (`H227 可燃液体`) 的**唯一法定法律事实判据**！
  - *Why 2?* 英文模板默认将 9.7 闪点设为无数据，而同步引擎在提取源文件事实时，漏掉了闭口闪点的跨语种迁移。
- **归正对策**：  
  将英文 Row 1 修正为 `Yellow transparent liquid`；Row 7 闭口闪点精准写入 `65 °C`，确保分类证据链绝对完整。

### 2.6 Section 14 出现 ADG 澳洲法规外生硬编码污染
- **问题现象**：  
  Section 14 出现澳大利亚危险品法规 (ADG Code) 的外生硬编码字样。
- **5-Whys 根因穿透**：
  - *Why 1?* 模板开发期曾参考了外资企业的国际模板，遗留了澳洲本地法规注释片段。
  - *Why 2?* 该硬编码违反了全系统核心不变量 `INV-ZERO-EXOGENOUS`（零外生法规污染公理）。
- **归正对策**：  
  在主审计套件中立项 `Section 14 零 ADG 污染与国际公约保全规范 (REQ-04)` 硬门禁，彻底剔除 ADG，并保全 MARPOL 73/78 与 14.6 参见章节。

### 2.7 Word/PDF 页脚畸形缩进 firstLine="8730" 导致首字截断
- **问题现象**：  
  在将 DOCX 转译为 PDF 时，多份文档第一页页脚右侧出现文本截断，页码与文档编码缺失首字符。
- **5-Whys 根因穿透**：
  - *Why 1?* 底层模板 `word/footer1.xml` 中存在历史脏代码 `<w:ind w:firstLine="8730"/>`。
  - *Why 2?* 该超大缩进将页脚段落强行向右推挤，在 Word 视口中勉强可见，但在 PDF 虚拟打印机解析时直接超出页面物理边距。
- **归正对策**：  
  在集中式主审计与清洗脚本中建立“页脚几何安全门禁”，强行清除畸形 `firstLine="8730"`。

### 2.8 英文版第 0 列标签字号暴增至 12pt (sz="24") 破坏全局拓扑
- **问题现象**：  
  英文版中，Section 8 的 `Hand protection:` 等标签异常放大为小四 12pt (`sz="24"` 加粗)，而全篇英文其他章节标签皆为 9.5pt (`sz="19"`)。
- **5-Whys 根因穿透**：
  - *Why 1?* 翻译引擎在从中文模板克隆样式时，直接把中文法定小四 (`sz="24"`) 复制到了英文节点上，未作字阶投影。
- **归正对策**：  
  确立 `英文标签第 0 列字阶全域均一性规范 (REQ-02 / DEF-12)`，全篇 16 章节表格第 0 列英文标签恒定收敛为 9.5pt (`sz="19"`)。

### 2.9 英文全篇微观空格与标点黏连瑕疵
- **问题现象**：  
  英文版文本中大量存在 `cyanide.In`（句号后无空格）、`2,000mg/kg`（数值与单位黏连）、`(SCBA).Do` 等西文排版瑕疵。
- **归正对策**：  
  全篇应用微观空格正则清洗管线，在句号、闭括号与后接大写字母间自动注入西文标准空格，在数值与物理单位间注入半角空格。

## 三、 EP-1501 覆写期全量问题穿透与根因清算

`EP-1501` 为水性环氧乳液，属于水性树脂核心品类。在覆写全生命周期中，经历了从“脱轨裸覆写”到“正规军流水线”的重大治理转变：

### 3.1 绕过标准流水线裸写脚本导致排版错乱、居中滥用与缺失中文版
- **问题现象**：  
  早期执行时，Agent 编写了独立的单文件 Python 脚本（`build_ep1501_en.py`）直改产出物，导致输出物中：
  1. **完全遗漏中文版**（仅交付了英文版）；
  2. **排版大面积居中对齐**，标签与值失去栅格对齐；
  3. **单元格跨页断裂**，页面出现大片刺眼空白。
- **5-Whys 根因穿透**：
  - *Why 1?* 施工 Agent 产生侥幸心理，以为“改改英文即可交差”，破坏了 MSDS Studio 笛卡尔积交付矩阵公理。
  - *Why 2?* 裸脚本未加载 `pipeline-engine.js`、`universal-editor-primitives.js` 等受控编排器，丧失了字体、字阶、标尺和缩进等数十项内置防御能力。
- **归正对策**：  
  彻底废弃临时裸脚本，构建专属受控批处理生产流水线 `web/scripts/generate_ep1501_standard_deliverables.mjs`，统一遵循标准 7 阶流水线生成 4 DOCX + 4 PDF 全套 8 格式。

### 3.2 GHS 危险性分类被篡改为“非危品”并外生虚增 P262/P280
- **问题现象**：  
  源文件明明载明 `对水环境有慢性危害，类别 3 (H412)`，但产出物却变成了“未被分类为危险品”，且凭空冒出了 `P262 不要沾入眼睛、皮肤或衣物` 与 `P280 佩戴防护用具`。
- **5-Whys 根因穿透**：
  - *Why 1?* 底层事实识别引擎未能准确匹配中文括号与长文本描述，导致 `facts.isHazardous` 被判定为 `false`。
  - *Why 2?* `normalizeContext` 引擎在非危险品分支下，强行执行了“防御性兜底”，自动清空了真实的 H412/P273/P501，并填入了通用的非危保底防范说明（违反了 `既有事实不可否定公理` 与 `INV-ZERO-EXOGENOUS`）。
- **归正对策**：  
  在受控流水线中明确锁定前置事实事实指纹：
  ```javascript
  const facts = { modelCode: 'EP-1501', isHazardous: true, isDangerousGoods: false };
  ```
  绝对保全 H412、P273、P501，彻底消灭外生捏造的 P262/P280。

### 3.3 Section 1 题头 1.1 产品名称未置空导致父级题头污染
- **问题现象**：  
  EP-1501 中文版中，Row 1 `1.1 产品名称：` 被填入了 `水性环氧乳液 EP-1501`，造成父级题头与其下的 `中文名称：` 发生语义重复。
- **归正对策**：  
  在 Step 2 规范强化中，显式清空 Row 1 值单元格，将 `水性环氧乳液 EP-1501` 规范下沉至 Row 2 `中文名称：`，Row 3 注入 `环氧水分散体`。

### 3.4 Section 2 模块间垂直间距过宽达两行空行 (480 dxa -> 220 dxa 紧实化)
- **问题现象**：  
  用户明确指出：“调整一下section2 的内容 间距，目前 标签-内容 与标签-内容间的间距大概是两行空行，需要调整成一行，紧实一点”。
- **5-Whys 根因穿透与几何精算**：
  - *Why 1?* 检查 document.xml 发现，Section 2 数据行（Row 1~5）的单元格内边距 `w:tcMar` 设置了：
    - `w:top="160"` dxa (8pt)
    - `w:bottom="160"` dxa (8pt)
  - *Why 2?* 检查段落属性发现，主要节标题（2.2、2.3、2.4、2.5）起始段落设置了段前间距：
    - `w:spacing w:before="160"` dxa (8pt)
  - *Why 3?* 相邻两个模块间的垂直总距离计算为：
    $$\text{间距} = \text{Row } N \text{ bottom (160)} + \text{Row } N+1 \text{ top (160)} + \text{Row } N+1 \text{ p before (160)} = 480 \text{ dxa (24pt)}$$
    在五号/小四字阶下，24pt 恰好等于 **整整两行空行**！导致页面纵向空间被大量浪费，排版松垮。
- **紧凑化重构对策**：  
  在 `generate_ep1501_standard_deliverables.mjs` 中构建 `compactSection2Spacing(eng)` 函数：
  1. 将 Row 1~5 单元格上下边距均压缩为 `top="60"` dxa (3pt), `bottom="60"` dxa (3pt)；
  2. 将 2.2、2.3、2.4、2.5 段前间距压缩为 `before="100"` dxa (5pt)；
  3. 重构后的模块间总间隙为：
     $$\text{紧实间距} = 60 + 60 + 100 = 220 \text{ dxa (11pt)}$$
     实测恰好呈现标准 **一行紧凑空行**，完美解决松垮问题。

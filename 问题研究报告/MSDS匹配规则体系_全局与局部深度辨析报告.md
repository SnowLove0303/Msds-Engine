# MSDS 匹配规则体系 · 全局与局部深度辨析报告

> **编制版本**：MSDS Studio v3.29 规约体系  
> **核心定位**：彻底厘清**全局匹配规则（通用底座协议）**与**局部匹配规则（各节专有业务策略）**的本质区别与绝对边界，确立系统在非标源文档抽取、槽位映射与模板注入中的核心架构防火墙。

---

## 零、架构总览：底座协议与业务插件的双层模型

在 MSDS 智能匹配中，最大的设计陷阱是**“规则串味与特例污染”**（例如将 Section 9 专有的“未测全删行”误当作全局规则去删其他章节的行，或把 Section 9 的“标签允许追加测试条件”特例误放宽为全篇标签允许随意篡改）。

为根除此类缺陷，系统确立如下**双层解耦架构模型**：

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                        【上层：全局匹配规则 (底座协议)】                         │
│                                                                                 │
│   与具体 Section 零耦合的通用底层机制、词法/句法解析、归一化、寻址、状态机与交接契约   │
│   (抽取解构 / 槽位寻址 / 通用清洗 / 真假缺失判据 / 六大指令集 / 跨语言同构 / 原子注入)   │
└────────────────────────────────────────┬────────────────────────────────────────┘
                                         │ 挂载业务策略插件 (只能在协议内收紧，绝不放宽)
┌────────────────────────────────────────▼────────────────────────────────────────┐
│                        【下层：局部匹配规则 (各节插件)】                         │
│                                                                                 │
│   绑定具体某一 Section (S1~S16) 的行业法规、化学特性、专属字段对齐与特殊排版策略        │
│   (S1三角色命名 / S2的H-P归组与5大路由 / S3组分双居中 / S8反直觉映射 / S9条件解耦 / S11分层毒理) │
└─────────────────────────────────────────────────────────────────────────────────┘
```

## 一、核心认知：全局匹配规则 vs 局部匹配规则

| 维度 | 全局匹配规则 (Global Matching Rules) | 局部匹配规则 (Local Matching Rules) |
| :--- | :--- | :--- |
| **本质定位** | **通用通信协议与引擎底座**（底座内核） | **业务规则插件与特定策略**（各节业务） |
| **适用范围** | 普适于 Section 1 ~ Section 16 全章节、八大交付物 | **仅绑定具体的某一个 Section**（有明确的 Section 指向） |
| **是否包含节名** | **绝对禁止包含任何特定 Section 业务特例** | 必须指明目标 Section 及该节的特定字段 |
| **核心职责** | 词法解构、标点清洗、语义寻址、状态机判定、注入交接 | 化学/法规专业转换（GHS反解、限定词解耦、毒理分层等） |
| **变异权限** | 定义统一合法的变异操作代码与安全约束 | 在全局授权的边界内细化该节的字段映射逻辑 |
| **层级关系** | **上位法（不可逾越的底座红线）** | **下位法（只能收紧全局，绝无权限放宽全局）** |

## 二、纯净的【全局匹配规则】（七大底层协议，零 Section 污染）

全局匹配规则只管**协议、机制、格式、状态机与交接**，绝不掺杂任何特定章节的业务特例：

### 协议 1：源事实抽取与文本解构协议 (Decomposition Protocol)
- **样式角色解耦**：同段落内，前置加粗 Run 识别为 `Label`，后置常规体 Run 识别为 `Value`；跨段粘连时，纯加粗段与紧邻纯常规体段自动绑定；
- **行内冒号语法**：按照 `^([^：:]{1,100})[：:]\s*(.+)$` 切分键值对，保护化学配比（`1:1`）与时间冒号；
- **前缀噪声脱敏**：匹配比对时统一剥离 `1.1`、`9.3`、`（1）`、`v1.` 等非标前缀噪声，以纯语义比对，但原始抽取序号在元数据中保留备查；
- **多实体单元格扁平化**：一个单元格内堆叠多个键值对时，按换行拆解为平铺的独立事实对象。

### 协议 2：语义槽位绑定与寻址协议 (Slot Binding Protocol)
- **槽位抽象概念**：全 16 节统一采用 `s{section}:{slot_id}` 规范槽位寻址，每个槽位配置多对一的别名库（Alias Group）；
- **语义优先，严禁位置推断（OW-029 铁律）**：**绝对禁止“源文件第 4 行写入模板第 4 行”的位置型推断**，必须通过语义归一化匹配目标槽位，未命中或歧义目标一律阻断；
- **独占与冲突裁决**：一个事实原则上绑定一个槽位；同名多事实且数值冲突时，自动触发 `REVIEW_AMBIGUOUS` 挂起，严禁随机覆盖。

### 协议 3：通用数值清洗与业务真值保护协议 (Sanitation Protocol)
- **不可见字符净化**：剥离 `\u200b`（零宽空格）、`\ufeff`（BOM）、多余空白，统一规范软换行 `\n`；
- **紧凑与业务换行保真**：有逻辑含义的多行在单元格内作为软换行保留，严禁拼成无标点的长文本；
- **合成斜杠处理**：列表型并列斜杠（`A / B / C`）转换为分行；固有名词（`通风/排气`、`有/无`）原样保护；纯斜杠孤行（`/`、`／`）强制清空；
- **化学与度量衡保真**：严格保护范围符号（`-`、`~`）、不等号（`>`、`<`、`≤`、`≥`）及国际单位制（`mPa·s`、`g/cm³`）。

### 协议 4：真假缺失判定与实质否定分流协议 (Missing vs. Negative Protocol)
- **纯缺失占位符通用判据**：
  命中 `^(?:无数据(?:资料)?|暂无数据|无可用数据|未测定?|未提供|—|-|no data available|not available|none)$`，判定为**真缺失**（数据不存在）；
- **实质否定结论保护判据（严禁误判为缺失！）**：
  命中 `不适用 (Not applicable)`、`非危险品`、`无危险反应`、`初沸点以下无闪点`、`未满足分类标准`、`无刺激/无致敏`，判定为**合规技术结论**，必须判定为 `MATCHED` 且 100% 保留！

### 协议 5：通用状态机与六大处置指令集 (Action Decision Engine)
每一个抽取事实计算后，必须且只能被赋予以下六大全局指令代码之一：
1. **`MATCHED`**：命中标准槽位且有有效数据或合规结论 ➔ 指令：原位写入模板值格；
2. **`PRUNED`**：命中槽位但属于未测/纯缺失，且被局部规则授权剪枝 ➔ 指令：第二遍执行整行安全删除；
3. **`EMPTY`**：源未提及但模板有槽位 ➔ 指令：值格保持清空或标准客户面 `无数据` 占位；
4. **`NOT_APPLICABLE`**：源明确标注不适用 ➔ 指令：保留不适用凭证；
5. **`UNMATCHED / EXTRA`**：源文档存在非标多余字段 ➔ 指令：存入备查清单或并入注槽；
6. **`REVIEW_AMBIGUOUS`**：多义、冲突或置信度不足 ➔ 指令：强行阻断并提示人工审阅。

### 协议 6：跨语言双向对齐与术语翻译协议 (Bilingual Alignment Protocol)
- **槽位同构**：中英文模板采用完全一致的 Slot ID 拓扑；
- **事实等价**：数值、CAS、浓度范围等技术指标双语 100% 共享唯一事实数据；
- **术语规范层**：英文映射强制调用专业术语词典库（`professional_translation_glossary`），严禁机翻直译，**严禁由中文输出直接翻译英文**。

### 协议 7：模板引擎安全交接契约 (Atomic Handoff Contract)
- **只写可编辑值格**：强制应用 **12pt（小四）非加粗** 字体，严禁破坏加粗标签；
- **倒序安全删行**：对标记为 `PRUNED` 的行，自底向上（从大索引到小索引）执行删除，防止行索引漂移；
- **联动连贯重排**：删行完成后立即触发 `renumberRecord`，重排可见序号；
- **终审零缺陷门禁**：发现未处理占位符或序号断档直接阻断。

## 三、各章节【局部匹配规则】（专属业务逻辑插件）

局部匹配规则是针对具体某一个 Section 的业务特殊性，挂载在上述全局协议下的**专属业务逻辑**：

| 章节 | 局部匹配规则（特定业务逻辑，有具体 Section 指向） | 为什么不能作为全局规则？（边界限定） |
| :--- | :--- | :--- |
| **Section 1<br>物料标识** | **三角色命名与双公司覆盖**：<br>1. 题头=型号；<br>2. 中文版 `产品名称` 留空，`中文名称` = 中文名+空格+型号；<br>3. 英文版 `Product name` = 专业英文名+空格+型号；<br>4. 供应商信息匹配冠志/国彩 5 项白名单字段。 | 这是针对企业特定产品标识与公司白名单的局部拼装算法，其他 15 节没有“名称留空”或“型号拼接”的概念。 |
| **Section 2<br>危险性概述** | **GHS 规范分行与 5 大路由独立映射**：<br>1. H 码与 P 码必须“逐码拆行，一码一行”；<br>2. P 语句按“预防措施、事故响应、安全储存、废弃处置”四大业务块归纳；<br>3. S2.8 健康危害必须按“吸入/食入/皮肤/眼睛/体征”5 大独立路由拆分，总论“未被分类”严禁抄入路由；<br>4. 象形图原图入格，无图仅依显式分类。 | 只有 S2 有 GHS 码、四大防范块与 5 大健康危害路由的概念，这些分行与归组逻辑绝不能套用到其他章节。 |
| **Section 3<br>成分信息** | **三列表格居中与动态增行**：<br>1. 提取组分名、CAS、浓度范围三要素；<br>2. 组分多于既有行时，触发样式行原位克隆；<br>3. 数据格强制**水平居中 + 垂直居中**；<br>4. 组分级 GHS/H 码为路由证据，严禁抄入 S2 题头。 | 全局值格统一要求“左对齐”，只有 S3 数据格特殊要求“水平居中”；动态克隆行仅限该节表格。 |
| **Section 4~7<br>急救/消防/泄漏/处置** | **功能性槽位等义映射**：<br>紧凑文案映射，去除换行伪影；严禁使用模板既有示例添加未授权建议；S4~S7 无行重建。 | 纯语义功能性槽位映射，无特殊表格变异。 |
| **Section 8<br>接触控制** | **反直觉语义对调与四列 OEL 嵌套处理**：<br>1. **反直觉对调**：源 8.1 暴露限值 ➔ 模板 8.2 工程控制；源 8.2 暴露控制 ➔ 模板 8.1 个体防护；<br>2. PPE 细分材质拆分（FKM/IIR/NBR）；<br>3. S8.2 四列嵌套表格（物质/依据/类型/数值）无源整块安全删除，有源实证替换，严禁合成无数据行；`建议：` 行源门控。 | 对调流转是针对模板历史特定版式的特殊映射；嵌套四列表格整块删除是 S8.2 专有结构，严禁在常规表乱删父表头。 |
| **Section 9<br>理化特性** | **唯一标签修改特权与未测强制剪枝**：<br>1. **全篇唯一特权**：源有明确测试条件（如 pH 溶液浓度、粘度温度）时，解耦并受控附于标签后；<br>2. **未测强制整行剪枝**：未测定或纯缺失项整行删除，终稿绝不见纯“无数据”理化项；<br>3. 剪枝后触发 5 宽槽（`9.1  `）连贯重排；<br>4. 严禁合并水溶性与粘度，NCO 独立。 | **最容易误犯的混淆点**！<br>“标签修改”和“未测必须删行”**仅仅是 Section 9 的专有特权**！其他章节标签一字不可改，其他章节缺失普通端点时允许保留 `无数据` 占位！绝不能全局化！ |
| **Section 10<br>稳定性反应性** | **禁配物与避免条件等义映射**：<br>仅等义概念映射；源文档缺失“应避免条件/禁配物”时该项直接隐藏消失，不留空行。 | 仅针对禁配与条件的无值整项隐藏。 |
| **Section 11<br>毒理学信息** | **最高优先级：分层毒理与三列行末格写入**：<br>1. 严禁标点切分，按“端点 -> 研究块 -> 字段 -> 值”分层提取；<br>2. 三列行前两列锁定加粗标签，仅末格可写；<br>3. 11.7 生育/致畸/体外遗传毒性仅同名源字段填入；<br>4. 局部题头去重（仅去除模板已拥有的 `皮肤-`、`眼-` 等题头），余下逐字保留；<br>5. 经皮/吸入保源直接评估话术，严禁编造 LD50/LC50。 | S11 的毒理研究块、三列行前两列锁定与局部题头去重属于医学毒理学的复杂专业结构，若当作全局规则去删其他章节的题头会导致内容被误删！ |
| **Section 12<br>生态学信息** | **生态毒性与导引说明注处置**：<br>生态毒性必进 12.1，模板前导说明注无源即删；说明注保留单格值槽。 | 生态学专属说明行处置。 |
| **Section 13<br>废弃处置** | **处置建议归纳**：<br>紧凑专业处置话术；源说明行并入模板单格注槽，保留末两列处置行。 | 废弃建议流转。 |
| **Section 14<br>运输信息** | **四大陆海空运输体系独立分行**：<br>公路铁路/海运/空运四运输方式独立分行映射，UN号/正式运输名/类别/包装组/特殊预防各一逻辑行。 | 属于国际危险货物运输法规（ADR/IMDG/IATA）的特定数据分行模型。 |
| **Section 15<br>法规信息** | **法规行收敛与固定题头保护**：<br>仅留源实证法规行并删尾空行；加粗题头（`其它的规定：/符合下列法规要求：`）为锁定题头非值槽，严禁覆盖。 | 法规文本专有的尾部空行清理与题头保护。 |
| **Section 16<br>其他信息** | **免责声明与修改记录归集**：<br>单格注值仍走 12pt 非加粗契约；免责声明源实证范围，无行重建。 | 声明与修订说明。 |

## 四、全局与局部的防火墙（防穿透三大定律）

1. **特例隔离定律（Anti-Leakage）**：
   - 任何带具体章节名字的业务逻辑（例如 S9 的测试条件加到标签后、S11 的局部题头去重、S8 的反直觉对调），在代码实现上必须封装在独立的 `SectionStrategy` 处理器中，**全局匹配核心引擎（Core Engine）一行业务代码都不能沾染**。
2. **状态驱动定律（State-Driven）**：
   - 全局引擎只产出通用状态（如 `MATCHED`、`PRUNED`、`EMPTY`）；具体哪一个 Section 的哪些字段应该被标记为 `PRUNED`，由该节的局部规则决定。全局引擎只负责依据这个状态去执行通用的倒序删行与重排。
3. **安全单向收紧定律（One-Way Tightening）**：
   - 全局规则立下的红线（12pt 非加粗、零臆造、加粗标签锁定、双语事实等价、跨公司白名单差异），局部规则只能在其内部进一步收紧，**绝无任何权利放宽全局红线**！

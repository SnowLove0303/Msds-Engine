## 一、 系统核心法定思想的严重失守：主仆颠倒的根因剖析

### 1. 尘封的最高法定宪法原则
在系统的早期架构立法（`覆写模块/给Agent的使用文档.md`、`ARCHITECTURE.md` 与全局规约）中，曾明确确立了四项不可动摇的黄金公理：
- **公理 A（内容守恒）**：**内容必须悉数继承源文件**。源文件中记载的每一条危险性声明、操作防护、急救措施、成分阈值与毒理数据，都是经过法定确认的业务事实，任何算法、脚本或 Agent 绝对无权擅自否定、删除、降级或替换为“无适用资料”。
- **公理 B（格式继承）**：**格式必须继承模板**。底模中的网格几何、列宽、边框样式、字体层级（G-11 契约）必须作为格式母版被严格继承。
- **公理 C（桥梁定位）**：**编辑器的作用是建立模板的覆写桥梁以保证产出文件的文本格式等符合要求且不被篡改**。编辑器是保证 OOXML 纯净性与所见即所得微调的工程通道。
- **公理 D（辅助定位）**：**智能匹配引擎的作用是效率辅助而非最终答案**。它只是帮人类快速初筛的提效工具，绝不是自以为是的终审裁决者！

## 四、 Web UI 界面与编辑器“零破坏改通栏”技术实现方案

用户明确指示：**“改通栏，但要求已有的 Web UI 界面不变（包括编辑器）”**。

### 1. 为什么通栏改造完全不需要改动 Web UI？
在现有的前端架构（[`web/src/main.js`](file:///F:/App%20Location/Guanzhi Tong/Skill/MSDS-Engine/web/src/main.js) 与 [`web/src/render-utils.js`](file:///F:/App%20Location/Guanzhi Tong/Skill/MSDS-Engine/web/src/render-utils.js)）中，编辑器的表格渲染逻辑是**基于底层引擎 AST 动态驱动的**：

```javascript
// 现有 render-utils.js 中的渲染机制（天然支持通栏行！）
row.cells.forEach((cell) => {
  // 当单元格 gridSpan 跨满全列，或者该行本身只有 1 个单元格时
  // 浏览器原生 <td> 自动占据 100% 宽度，并承载 contenteditable 编辑区域！
});
```

- **绝对不变的资产**：
  - [`web/src/styles.css`](file:///F:/App%20Location/Guanzhi Tong/Skill/MSDS-Engine/web/src/styles.css)：**1 像素不改，0 字节变动**；
  - [`web/index.html`](file:///F:/App%20Location/Guanzhi Tong/Skill/MSDS-Engine/web/index.html)：**1 行不加，结构完全冻结**；
  - 顶栏、Ribbon 工具栏、左侧 Section 导航、右上角导出按钮：**完全保持原样**。
- **纯数据驱动的通栏呈现**：
  - 当 Section 2 处于通栏模态时，底层的 `engine.records[1].rows[1]` 只有一个单元格（`gridSpan="2"` 或 `cellCount === 1`）；
  - Web 编辑器会自然而然地将其渲染为一个通栏的富文本编辑框，用户在里面可以随意看、随意敲键盘换行微调；
  - 导出的 DOCX 也是纯正的单单元格通栏，**在视觉上和使用体验上完全浑然天成，丝毫不破坏已有 UI 界面！**

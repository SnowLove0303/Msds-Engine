# Proposal: 全景多维深度审计与模板拓扑识别层动态解耦

## Why
在完成 Context 2 初次直接写入现有编辑器并成功导出八格式交付物至 `01-2 水性羟基聚氨酯树脂 HPU\HPU-7651` 后，初步排查已经揭示出当前产出物在排版、字号、对齐、英文中文残留及底模死数据外泄等诸多细节问题；同时，现有匹配引擎在提取拓扑结构时与特定母版存在硬编码耦合，缺乏随母版结构变动而自适应演进的通用性。
用户明确指示：
> “1.先进行全面审计，从页眉页脚，到16个section，包括内容、表格格式、文本格式、字号、文本位置等，以及之前要求的缩进、对齐、剪枝等等（不止这些），进行全方位审计，然后写一份详细的md报告给我，16个section+页眉页脚或多或少存在些问题；2.当前的拓扑结构有点与模板绑死了，我希望先将拓扑层与模板分开来，做一个识别层，识别模板的结构并将其作为当前覆写产出的拓扑层使用，当模板更换时，拓扑结构随之改变；”

为了彻底厘清当前交付物的全部缺陷清单，并从根本上解决拓扑结构与母版的硬编码耦合问题，本方案确立：
1. **全要素全景多维深度审计**：从页眉页脚到 16 章节，全面覆盖内容保真、表格格式、文本格式、字号字阶、文本位置、悬挂缩进、激光制表位、历史剪枝等，出具详尽的 Markdown 审计报告；
2. **构建独立模板识别层 (Template Recognition Layer)**：将拓扑结构与固定母版彻底解耦，动态透视解析任意母版 DOCX 的表格网格、槽位属性、章节边界与父子标签关系，作为下游覆写生成的拓扑底座；
3. **实现模板更换拓扑自适应**：当母版更新或更换时，拓扑结构随之自动改变，实现真正的自适应覆写。

## What Changes
1. **编写全维度全要素审计探针与报告生成器**：
   - 深入审查 `HPU-7651` 八格式交付物（中英 DOCX + PDF）；
   - 提取页眉、页脚及 16 章节的实际 XML DOM 属性（字号 `w:sz`、字体 `w:rFonts`、缩进 `w:ind`、对齐 `w:jc`、边框 `w:tblBorders`、行高列宽等）；
   - 输出详尽的《HPU-7651 MSDS 八格式全维度全景深度审计报告.md》。
2. **研发模板拓扑识别层 (`web/src/template-topology-recognizer.js`)**：
   - 废除对固定模板的硬编码假设；
   - 动态载入母版 DOCX，自动解析 16 章节表格索引、行列分布、单元格语义角色（Header / Label / Value / Explanation）、边框与列宽特征；
   - 导出结构化模板拓扑蓝图（Template Topology Blueprint）。
3. **改造匹配引擎以消费动态模板拓扑**：
   - 在 `web/src/smart-matching.js` 中新增动态拓扑匹配接口 `matchContext1ToDynamicTemplateTopology(facts, templateTopology, variant)`；
   - 业务事实与母版空间拓扑通过动态插槽咬合，实现母版更换时拓扑随动。

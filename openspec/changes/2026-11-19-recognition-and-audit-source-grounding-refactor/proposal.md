## 1. 变更背景与动机 (Context & Motivation)

在对典型水性树脂源文件（如 `PA-4902`）进行底层 OOXML 原文与识别模块输出的深度对账中，发现两大系统性瓶颈：
1. **识别模块（`web/src/recognition-engine.js`）底层鲁棒性不足**：
   - GHS 分类对“无/不适用”否定词未作过滤，导致将 `GHS危险性类别: 无` 误判为危化品（`isHazardous = true`）；
   - 信号词同义词遗漏“警告词”，导致 `警告词：警告` 提取为 `signalWord: null`；
   - 防范说明过度依赖 `P\d{3}` 编码，当源文件为纯中文散文时，四大防范组（prevention/response/storage/disposal）全量丢失；
   - Section 4 急救（皮/眼/一般）、Section 5 消防（灭火剂/防护设备）、Section 7 操作及 Section 10 分解反应等顶层对象存在漏项；
   - Section 3 特殊中和成盐附注未在顶层结构化挂载。
2. **审计模块（`web/scripts/run_master_msds_audit.mjs` & `lint_source_grounding.mjs`）缺乏深度源文档穿透对账**：
   - 现有集中式中央主审计主要针对产出物自身排版与固定模版断言，缺乏强制性的源事实 1:1 双向物理对账；
   - 存在“象形图：无”被误测为存在象形图的浅层正则缺陷；
   - 未将 `lint_source_grounding.mjs` 的高强度源事实对账全面接入主审计流程，容易形成脱离源文件的假阳性放行。

## 2. 1:1 需求物理对账矩阵 (RTM Injection)

| 需求编号 | 需求名称 | 核心行为契约与验收标准 |
| :---: | :--- | :--- |
| **REQ-01** | GHS 危险性属性精准二分与否定语义过滤 | 过滤“无/不适用/不属于危险物/not classified/none”，非危源文件输出 `isHazardous = false`，提取无危害说明文本 |
| **REQ-02** | 警示词与信号词全量同义词覆盖 | 支持“信号词/警示词/警告词/Signal Word”等效匹配，捕获“警告/危险” |
| **REQ-03** | 散文防范说明纯文本后备解析器 | 当缺少 P 编码时，自动切分纯中文散文句子并精准分流至四大法定义务组（预防/响应/储存/处置），消除全空数组 |
| **REQ-04** | 全章节顶层结构化业务事实完整性增强 | 补全 S4 皮肤/眼睛急救、S5 合适/不合适灭火剂与自供气呼吸器（消除空对象）、S7 安全操作、S10 分解产物与危害反应 |
| **REQ-05** | Section 3 特殊注意中和成盐说明结构化抽取 | 捕获成分表下方的中和剂已成盐、游离浓度 <1.0% 等化学背景事实，挂载至 `componentsNotes` |
| **REQ-06** | 审计模块强制源文件 1:1 物理对账审计 | 主审计套件强制集成源文件客观事实对账，穿透核验 GHS 分类、OEL 限值、运输非危与温控、19 项理化数值及 CAS 组分 |
| **REQ-07** | 全局通用性准则与零过拟合硬阻断 | 全量面向全品类通用，绝对禁止单型号硬编码特判，严格通过 `npm run lint` 0 违规 |

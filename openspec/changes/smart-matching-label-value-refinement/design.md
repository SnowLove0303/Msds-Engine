# Design: 智能匹配标签-值解构提炼与字段映射基建

## Context

参见 `proposal.md`。在 MSDS Studio 中，`docx-engine.js` 负责从 DOCX XML 中解析出表格行、单元格与段落数据；`smart-matching.js` 负责从识别记录中抽取键值对行（`rawPairs`），并与模板 16 个章节标准插槽注册表（`SECTION_SLOT_REGISTRY`）进行语义对齐绑定。

在非标 DOCX（特别是将多个子小节、多项测试数据聚合排在一个大单元格内的文件）中，简单的“一行一格 = 一个键值对”导致整篇段落被当做单一字段值塞入第一个命中的插槽中，造成“一槽挤爆，其余全空”的失衡现象。

## Goals / Non-Goals

**Goals:**
- 在提取 `rawPairs` 的前置阶段，对 Section 2 和 Section 11 的聚合单元格实施多段落/子小节原子化解构；
- 将解耦后的独立事实对赋予精准的标准/局部标签，使语义路由器能将其准确分发至各自的目标插槽；
- 在 Section 1 中支持复合品名型号的分流提取；
- 在 Section 16 中确保免责声明长文本单一独占，消除冗余镜像；
- 保持 0ms~5ms 内纯前端纯 JS 高性能计算，不引入外部庞大 NLP 依赖。

**Non-Goals:**
- 不修改 `docx-engine.js` 的 DOCX 底层底层 XML 解析核心（保持识别层稳定）；
- 不修改模板的行数与只读列结构（严格遵守模板几何不变性）。

## Decisions

### 1. 前置解耦切分点设计 (Decoupling at `rawPairs` Stage)
选择在 `smart-matching.js` 的 Section 行遍历初期（即构建 `rawPairs` 时）介入，而不是在最后模板注入时硬编码切分。
- **理由**：如果在 `rawPairs` 阶段就将 1 个大单元格还原成 N 个独立键值对，下游的语义匹配器、别名库、冲突检测、PRUNED/EMPTY 统计、编辑器三屏同览预览就能天然共享这一解构收益，无需修改下游消费者代码。

### 2. Section 2 专用复合块前置解耦 (`decoupleSection2CompoundBlocks`)
- 针对单单元格或多行文本，利用关键特征锚点：
  - `锚点 A (2.1 分类)`: `/(?:^|\n)\s*(?:2\.1|物质或混合物的分类|GHS危险性类别)/i`
  - `锚点 B (2.2 标签要素/象形图)`: `/(?:^|\n)\s*(?:2\.2|标签要素|GHS-象形图)/i`
  - `锚点 C (2.3 其他危险)`: `/(?:^|\n)\s*(?:2\.3|其他危险|其他危害)/i`
- 切出三段：
  - 子项 1：提取分类结论（如“根据GHS不属于危害化学品”），生成 `rawLabel: "2.1 GHS危险性类别："`，`rawValue: "根据GHS不属于危害化学品"`；
  - 子项 2：象形图状态（如非危品无象形图），生成 `rawLabel: "GHS象形图："`, `rawValue: "无象形图"`；
  - 子项 3：其他危险，生成 `rawLabel: "2.8 其他危险："`, `rawValue: "无适用资料。"`。

### 3. Section 11 毒理学聚合长文本端点切片 (`decoupleSection11ToxicologyBlocks`)
- 检测文本是否包含多个毒理学核心端点（`急性毒性`、`皮肤刺激`、`粘膜刺激/眼睛刺激`、`致敏性/皮肤致敏`、`致突变性/Ames`、`STOT`、`CMR` 等）；
- 利用端点边界切片，将大段文本拆分成针对各个具体毒理指标的独立段落，分别赋予对应端点标签（如“急性毒性：”、“皮肤腐蚀/刺激：”、“严重眼睛损伤/眼刺激：”等）；
- 节级通报（“该产品无可用的毒理学研究”）独立保留。

### 4. Section 1 品名型号分流与 Section 16 去重
- Section 1：若 `product_name` 中包含清晰的规格型号（如 `PU-2341E`），且 `model` 槽位为空，自动分流出型号注入 `model` 插槽；
- Section 16：若检测到 `disclaimer` 已填充了免责声明，`16.1 other_info` 槽位不再重复填充相同的免责文本。

## Risks / Trade-offs

- **[Risk]** 某些源文件的子标题没有换行（如“分类GHS危险性类别:根据GHS不属于危害化学品2.2 标签要素”紧密相连）。
  - **Mitigation**: 切分正则不依赖 `\n`，支持行内以数字标号 `2.2` 或标志性中文词无缝切分。
- **[Risk]** 影响现有其他测试用例的匹配结果。
  - **Mitigation**: 新增解耦逻辑仅在检测到复合标记时触发，单一普通行完全走既有逻辑；保持现有单元测试全部通过。

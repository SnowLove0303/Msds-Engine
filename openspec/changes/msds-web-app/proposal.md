# Proposal

## Why

现有 MSDS 能力分散在两个 Windows/Python 桌面模块中：识别模块能读取 DOCX 的表格、段落、字符样式、合并关系和源 OOXML，覆写模块能以 CN/EN 冠志模板安全编辑并审计 DOCX，但用户必须分别启动桌面工具，无法在同一个页面完成“导入核对”和“模板编辑”。现在需要把这两条工作流汇聚为一个易于演示和继续扩展的网页原型，同时保留源 DOCX 的版式证据和模板的结构安全边界。

## What Changes

- 在 `F:\Skill\MSDS\web` 建立可直接运行的单页 MSDS 工作台，提供统一导航栏、工作区切换、状态提示和响应式布局。
- 新增“DOCX 识别”工作区：支持拖拽/文件选择导入 `.docx`，解析 16 个 MSDS Section 表格、段落、字段候选、合并单元格、图片和基础文字样式；以统一的 16 节表格视图展示，并提供源文档原版式预览、结构化表格、格式/覆盖率检查与 JSON 导出。
- 新增“模板编辑器”工作区：内嵌 CN 冠志和 EN 冠志模板，按原模板的章节、行列、合并关系和标签/值角色展示可编辑字段；默认只允许编辑非加粗值，标签、序号和结构行保持保护，Section 9 标签编辑需要显式开启。
- 支持模板行的安全新增/删除、同章节连续重编号、Section 9 等宽前缀保持、审计结果提示以及“导出编辑后 DOCX”下载；源文件和内嵌模板始终只读。
- 将网页视觉收敛为白底、低装饰、少说明的工作台；结构化表格直接采用源 DOCX 的字体、字号、段落、边框、底纹、列宽、合并关系和行高证据，不再使用深色卡片皮肤作为表格样式。
- 使用现有模块的真实模板资源和可验证的前端数据模型，不修改 `识别模块`、`覆写模块` 中的既有 Python 代码。

## Capabilities

### New Capabilities

- `msds-document-inspector`: 在浏览器内导入 DOCX，生成 16 节结构化识别结果，统一展示表格与源版式，并输出识别覆盖率/警告/JSON。
- `msds-template-editor`: 基于内嵌 CN/EN 模板进行受保护的值编辑、行操作、重编号、审计和 DOCX 导出。

### Modified Capabilities

无。当前项目没有已有 OpenSpec capability；本次为网页端新能力。

## Impact

- 新增 `web/` 前端工程、静态资源、内嵌模板副本和运行说明；预期使用 Vite、原生 TypeScript/JavaScript、JSZip 与 `docx-preview`（或等价的本地依赖）。
- 浏览器端不依赖后端服务；DOCX 解析、预览、编辑和导出都在本地完成。原版式预览以源 DOCX 的浏览器渲染为依据，结构化视图以 OOXML 解析结果为依据，两者并列呈现，避免用重建表格替代源文档证据。
- 识别目标范围为 `.docx`；旧版 `.doc`、Word/WPS COM 导出 PDF 等桌面模块专属能力不在网页首版范围内。

# Proposal

## Why

当前 MSDS 系统的智能匹配中间层虽已具备初步的插槽映射与界面渲染能力，但底层缺乏深度解耦、严密防穿透的**全局匹配规约引擎（Global Matching Engine Protocol）**。非标源文档格式高度异构（段落内粗细体混合、行内冒号误切、非标序号前缀污染、列表斜杠与固有名词混淆、真假缺失与合规否定结论混同）。

若未经规范化先期开发纯净的全局约束底座，容易导致各章节专有特例向外渗透，引发“规则串味”、“错误误删有效结论”或“直接修改模板导致样式崩坏”。因此，必须先行将脱离具体 Section 业务污染的纯净全局匹配规则（词法解构、归一化寻址、通用清洗、真假缺失判定、六大状态机及安全注入交接）深植于匹配引擎底层核心中。

## What Changes

- **构建纯净全局匹配引擎底层架构 (`web/src/smart-matching.js`)**：
  - **源事实解构器 (Decomposition Engine)**：实现粗细 Run 分离解析、行内冒号语法切分（含化学配比与时间冒号保护）、自造序号前缀脱敏（剥离 `1.1`、`9.3`、`（1）` 等前缀但不丢失溯源）、多实体单元格扁平化展开；
  - **语义槽位绑定与寻址协议 (Slot Binding Protocol)**：抽象统一 `s{section}:{slot_id}` 槽位概念，严禁任何基于行号的位置推断（落实 OW-029 铁律），完善独占性检查与冲突挂起机制；
  - **通用数值清洗与保真器 (Sanitation Engine)**：剥离不可见字符（`\u200b`, `\ufeff`），规范软换行 `\n`，区分列表并列斜杠与固有名词（`通风/排气`），保真化学范围线与度量衡符号；
  - **真假缺失与实质否定分流引擎 (Missing vs. Negative Engine)**：精准匹配纯缺失正则，建立“实质否定结论”（`不适用`、`非危险品`、`无危险反应`、`初沸点以下无闪点`、`未满足分类标准`、`无刺激`）绝对保护机制，100% 标记为 `MATCHED` 并杜绝误剪枝；
  - **统一状态机与六大处置指令集 (Action Decision Machine)**：为每一个提取事实赋予标准指令代码（`MATCHED / PRUNED / EMPTY / NOT_APPLICABLE / UNMATCHED / REVIEW_AMBIGUOUS`）；
  - **长文本说明性段落分类归集器 (Narrative Note Dispatcher)**：将非表格大段散文（毒理可用性说明、生态可用性说明、法规清单、免责声明）智能路由至单格注槽；
  - **模板引擎原子安全交接契约 (Atomic Handoff Contract)**：确保注入时仅操作可编辑值格（12pt 非加粗），对 `PRUNED` 执行自底向上倒序安全删行，删后联动触发连续重新编号。
- **Web 端状态与工作台无缝接入**：
  - 将重构后的全局匹配引擎接入 `state.matching`，实时计算并展示精准匹配结果。
- **自动化测试回归体系**：
  - 在 `web/tests/smoke.mjs` 中添加针对粗细拆分、冒号保护、实质否定不误剪、六大状态流转、倒序删行及重排的全面回归断言。

## Capabilities

### New Capabilities
- `global-matching-engine`: 定义并实现脱离具体 Section 业务污染的纯净全局匹配协议（包含事实解构、槽位寻址、通用清洗、实质否定保护、六大状态机以及模板安全注入契约）。

### Modified Capabilities
- 无（系统既有外围功能保持向后兼容）。

## Impact

- `web/src/smart-matching.js`: 重构并强化全局匹配引擎核心算法、抽取解构器、缺失判定器与状态机。
- `web/src/main.js`: 接入更新后的全局匹配状态与审计结果。
- `web/tests/smoke.mjs`: 增加针对全局匹配协议的自动化单元与集成测试。
- 零破坏性：不修改基准模板物理字节，保持 DOCX 模板加粗标签与 16 表结构绝对不变。

# 提案：全视图表格标签中文首字绝对垂向对齐治理 (All Views Label Chinese First Char Alignment)

## 1. 变更背景与核心痛点
在 MSDS Studio 的三大核心视图中：
1. **01 DOCX 识别 (Inspector)**
2. **02 智能匹配工作台 (Smart Matching Workbench)**：原始提取表与匹配标准模板表
3. **03 模板编辑器 (Template Editor)**

用户反复强调的核心排版铁律是：**“凡涉及到表格的，标签中文首字必须绝对垂直共线对齐”**。

然而当前系统的渲染逻辑存在严重的割裂与偏差：
1. **带序号行与无序号行基线脱节**：
   - 带序号行（如 `1.1  产品名称：`、`10.1  化学稳定性：`）采用了 `--sequence-width: 2.8rem` + `gap: 0.35rem` 的 Grid 双槽位，首字 X 坐标约为 `3.15rem`；
   - 无前缀序号的行（如 `中文名称：`、`化学品分类：`、`供应商名称：`、`供应商地址：`、`电话：`、`传真：`）被归类为子行，因缺少序号而跌出 Grid，被赋予 `.label-child-row` 的硬编码 `padding-left: 2.2rem`，导致首字位于 `2.2rem`；
   - 无序号的父级或说明行（如 Section 15 法律法规项或未带号父项）则为 `padding-left: 0`；
   - 导致同一表格内标签首字在 `0`、`2.2rem`、`3.15rem` 之间跳跃参差不齐。
2. **模板编辑器完全脱离双槽位 Grid**：
   - `renderEditorCell` 中，对锁定标签与编辑标签直接输出了包含内联序号字符串的普通 div（`<div class="locked-label">${cell.labelText}</div>`），完全未挂载 `.label-line-grid`；
   - `1.1` 的字符宽度推动 `产` 向右偏，而 `中文名称：` 顶在左边界，导致模板编辑器内所有标签首字完全失准。
3. **三大视图未共享槽位几何契约**：
   - 识别页、匹配工作台的两张表（原始表与标准表）和模板编辑器缺乏统一的“序号槽（固定宽） + 标签文本槽（统一左起始线）”闭环支撑。

## 2. 变更目标与验收准则
1. **全 16 章节标签中文首字绝对共线**：
   - 凡属于表格数据行（Row > 0）的标签单元格，无论是否带有前缀序号（`1.1`、`10.1` 或无序号 `中文名称：`），**其中文首字必须坐落于完全相同的水平 X 坐标基准线上**（误差 0px）。
2. **空序号槽位占位符（Empty Sequence Slot）**：
   - 无前缀序号的标签行，在 Grid 第一列强制输出不可见、等宽的占位槽 `<span class="sequence-slot empty-slot" aria-hidden="true"></span>`，宽度与带号行的 `--sequence-width`（2.8rem）+ 列间距完全一致。
3. **三大视图全景覆盖**：
   - `01 DOCX 识别`：`renderStructuredTable` 呈现的数据表格标签中文首字 100% 垂直对齐；
   - `02 智能匹配`：原始提取表格与匹配模板表格的标签中文首字 100% 垂直对齐；
   - `03 模板编辑器`：`renderEditorCell`（包括锁定展示与双击编辑）拆分序号槽与标签槽，标签中文首字 100% 垂直对齐。
4. **长标签多行悬挂缩进保持**：
   - 换行长标签（如 11.8 特异性靶器官毒性）续行文本严格约束在第二槽位 `.label-text-slot` 内折行，与首行中文首字严格垂直对齐。
5. **既有防退化保障**：
   - Section 3 表头三列居中/加粗/下划线不受破坏；
   - 42 项问题清单自动化回归测试与 Smoke Test 100% 通过。

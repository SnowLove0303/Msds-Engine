# Proposal: 通用页面格式与页脚拓扑强化识别及产出物页脚统一治理

## 1. 需求背景与使命 (Background & Mission)
针对用户指令：“写入强化识别能力，并解决当前产出物页脚纯在的统一问题，需要注意的是：请务必遵守 通用性原则，允许强化识别能力和模板使用能力，但不允许将单一模板固定为通用模板使用，要保证拓扑结构的灵活性！”

系统需彻底打破对特定母版（如冠志/国彩既有模板）和特定行列坐标（如写死 Table 0, Row 0, Cell 1）的死硬编码依赖。通过在通用模板拓扑识别层（`template-topology-recognizer.js`）强化页面几何（`w:sectPr`）与页脚多插槽（`slots.revisionDate`, `slots.entityModel`, `slots.pageNumber`）的自适应识别能力，实现任意母版的结构化认知；同时下游覆写与修整模块（`docx-engine.js`）完全基于拓扑插槽指针进行就地无损更新，彻底治愈产出物页脚历史遗留的异形字符（如“P修订日期”）、非标空格与排版断层问题。

## 2. 1:1 需求物理对账矩阵 (Requirements Traceability Matrix)

| 需求编号 | 需求项名称 | 用户原始语义锚点 | 核心使命与验收边界 |
| :--- | :--- | :--- | :--- |
| **REQ-TOPO-01** | **强化模板拓扑识别能力** | “写入强化识别能力……允许强化识别能力和模板使用能力” | 赋予系统对任意母版页面格式（纸张尺寸、边距、网格）与页脚插槽（修订日期、主体型号、页码）的自动化动态识别能力，无需人工干预即可提取拓扑蓝图。 |
| **REQ-FOOTER-02** | **产出物页脚统一治理** | “解决当前产出物页脚纯在的统一问题” | 针对当前产出物页脚存在的排版与内容不一致（如历史遗留字符残留、样式偏差、主体未对账等），实现基于拓扑插槽的统一治理与就地规范化。 |
| **REQ-GEN-03** | **通用性准则硬约束** | “请务必遵守 通用性原则……但不允许将单一模板固定为通用模板使用” | 严禁将现有特定模板（如冠志/国彩特定排版格式）硬编码或固化为全局唯一的通用标准，系统底层必须对不同模板保持完全中立与通用兼容。 |
| **REQ-FLEX-04** | **拓扑结构自适应灵活性** | “要保证拓扑结构的灵活性！” | 保证对不同几何形态的页脚拓扑（如 2×2 网格、1×2 网格、多行多列表格或纯段落制表位排版）均具备灵活承载与自适应适配能力，杜绝死板假设行列坐标。 |

## 3. 架构影响与爆炸半径 (Impact & Blast Radius)
- **拟变模块**：
  - `web/src/template-topology-recognizer.js`：新增 `recognizePageFormatting` 与 `recognizeFooterTopology`，并在 `recognizeTemplateTopology` 中挂载；
  - `web/src/docx-engine.js`：将页眉页脚提取与覆写逻辑重构为优先基于 `footerTopology` 插槽指针寻址，剥离硬编码特判；
  - `web/tests/test_universal_page_and_footer_topology.mjs`：新增专用端到端自动化验证套件。
- **保护不变量**：
  - `MSDS_UNIVERSAL_DESIGN_TOKENS_IMMUTABLE` 封印块绝对只读保留；
  - 16 章节正文表格几何与内容提取链路保持原样；
  - 既有微调工具、预设治理层与导出管线接口完全向后兼容。

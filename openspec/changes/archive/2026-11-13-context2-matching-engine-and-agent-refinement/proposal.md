# Proposal: Context 2 匹配引擎融合与 Agent 全局/局部规范二次打磨流程重构

## 一、 业务动机与架构重构 (Why)
在以往的 MSDS 处理流程中，系统在提取源文件事实后，依赖独立的 `pipeline` 模块（如 `pipeline-engine.js`）进行黑盒清洗与装配。这种设计存在逻辑割裂、中间状态黑盒化、难以适配复杂源文档多元形态等瓶颈。

为了彻底升级 Context 2 的产出质量与架构纯粹性，本次变更执行重大架构重构：
1. **彻底废除 pipeline 独立概念**，将其所有核心数据承接与格式化职能深度融入**匹配引擎 (Smart Matching Engine)**；
2. **确立“匹配引擎结构初筛 + Agent 规范二次打磨”两阶流水线**：
   - **第一阶（匹配引擎结构拓扑映射）**：将 Context 1 识别结果送入匹配引擎，依据源文件内容结合企业正式底模的拓扑学几何结构（16 章节表格、列数、固定行与槽位），执行多元化映射，先期确定好合规的**基本结构骨架**（恪守“内容来源于源文件，结构来源于模板”公理）；
   - **第二阶（Agent 认知打磨）**：由大模型 Agent 依循全局不变量规范与 16 章节局部细化规范，对基本结构执行二次深度精细打磨（专业地道双语英译、非危防虚增、度数符号西文化、毒理终点拆分）；
3. **精准赋能下游编辑器受控写入**：
   - 编辑器写入的准确性高度取决于 Context 2 的准确性；本次重构使 Context 2 成为直接驱动万能编辑器原语（`universal-editor-primitives.js`）的高精度事实数据基座。

## 三、 拟变范围与影响评估 (What Changes)
- **纳入范围**：
  - 增强 `web/src/smart-matching.js`，吸收原 pipeline 的槽位匹配与结构映射职能，提供纯净的结构拓扑初筛接口 `matchContext1ToTemplateTopology(facts, templateVariant)`；
  - 规范化 Context 2 标准 Schema（包括中英文双轨槽位、操作意图字典、富文本标记）；
  - 建立 Context 2 生产与验证统一入口脚本 `web/scripts/produce_context2.mjs`，支持匹配引擎结构初筛与 Agent 二次打磨；
  - 编写 Context 2 独立检验脚本 `web/scripts/audit_context2_accuracy.mjs`，确保提供给编辑器的输入 100% 准确。
- **排除范围**：
  - 不篡改 Context 1 识别引擎与机械审计器；
  - 不篡改底层通用编辑器万能原语逻辑。

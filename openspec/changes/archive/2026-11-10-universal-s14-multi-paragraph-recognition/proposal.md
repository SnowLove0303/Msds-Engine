## 1. 变更背景与用户核心指令

在对 `PU-2346A` 进行生产验收时，用户敏锐指出系统底层识别程序在处理复杂多行单元格时存在严重的事实丢失与分类混淆缺陷：
> “section14 对源文件内容的理解与分类还是不到位，特别是14.6 特殊防范措施及其子标签 附加信息，很明显啊，14.6 特殊防范措施 的值 是 “参见6-8节” ，而其子标签值是：具可燃性。温度不可高于+35℃，温度不可低于-10℃。远离食物、酸和碱。 ，说明 识别程序底层对这类问题的通用型理解能力与处理能力不是很足”
> “执行，此项请对识别模块进行通用型优化，请务必遵循Ps-openspec 关于系统底层的改动要求，需要注意的是，我们将整个msds studio 划分为底层（模板与拓扑结构、编辑器、映射、机械审计、识别模块、匹配引擎、MCP调用）和执行层（SKILL、全局规范与局部规范、审计规范），核心区分是 通用型固化层与具体执行层，一般来说只允许改执行层，但有些通用性问题或工作流调用普遍性存在的问题则需要改动通用固化层去解决，请严格遵守Ps-openspec 关于系统底层改动的说明”

### 根因深度穿透 (5-Whys Root Cause Analysis)
1. **Why 1**: 为什么 14.6 的“参见6-8节”在最终交付物中丢失，反而显示为“特殊防范措施：附加信息：具可燃性...”？
   - 因为在 `buildDynamicSection14Table` 中，程序使用单行正则表达式跨单元格强行匹配 `srcS14Text`，将标签与值粗暴拼合，直接漏掉了交叉引用指引“参见6-8节”。
2. **Why 2**: 为什么 `srcS14Text` 会把整行单元格内容粘连在一起？
   - 因为在底层读取阶段，直接调用了 `row.cells.map(c => c.text).join(' ')`，单元格内部的多段 `<w:p>` 段落换行丢失，退化为无结构的扁平长字符串。
3. **Why 3**: 为什么源文件中会有多个标签和值挤在一个单元格？
   - 源文件 Row 3 的 Col 0 包含了 7 个段落（`14.3运输危险级别：`、`14.4包装类型：`、`14.5环境危险：`、`14.6特殊防范措施`、`附加信息：`、`""`、`14.7按《MARPOL73/78》...`）；而 Col 1 也包含了 7 个段落（`3`、`III`、`否`、`参见6-8节`、`具可燃性...`、`远离食物...`、`不适用`）。这是业界典型的“多段对齐压缩单元格”排版。
4. **Why 4**: 为什么识别模块未能还原这种 1:1 的段落级映射？
   - 原 `recognition-engine.js:parseSection14` 只简单检查了 `isNonDangerousGoods` 和 `unNumber`，根本没有建立段落级语义对账与主子标签从属树识别能力，属于通用底层能力缺失。
5. **Why 5**: 为什么此前未能前置发现？
   - 依赖局部正则兜底（Sink 处防御性处理），违背了“逆向数据流穿透溯源至 Producer”的承重墙原则。

## 3. 拟解决的核心架构方案

1. **底层 Producer 升级（`recognition-engine.js`）**：
   - 抽象通用原语 `extractMultiParagraphCellPairs(row)`：当单元格包含多个段落时，通过段落行号与语义标签自动建立 1:1 或 1:N 映射关系；
   - 重构 `parseSection14(record, facts)`：将源文件 Section 14 解析为高保真结构化事实对象（包含 `unNumber`, `properShippingName`, `hazardClass`, `packingGroup`, `environmentalHazards`, `specialPrecautions: { primary, additionalInfo: { label, items } }`, `marpol`）。
2. **构建层通用下沉（`pipeline-engine.js`）**：
   - 重构 `buildDynamicSection14Table`：直接消费由底层识别出的结构化数据，不再依赖易崩塌的正则匹配；
   - 采用标准规范排版：
     - Row 6 (14.6): Col 0 `14.6 用户特殊防范措施：`，Col 1 `参见6-8节`；
     - Row 7 (附加信息): Col 0 `附加信息：`（挂载 `left="420"` 左缩进，垂直平齐），Col 1 承载 2 行实测值（纯净左对齐）；
     - Row 8 (14.7): Col 0 `14.7 按《MARPOL73/78》公约附则II和IBC规则：`，Col 1 `不适用`。
   - 中英文双语行数严格 1:1 对称同构（各 9 行）。
3. **中央主审计套件（`run_master_msds_audit.mjs`）**：
   - 同步更新 Item 151（容纳包含附加信息子行的 9 行标准危化品运输拓扑，核销“参见6-8节”事实）。

# Design: Section 2 智能匹配无值删行机制与跨行排版一致性方案

## 1. 架构总览

在 MSDS 标准规约中，目标模板是规范容器，但不是教条式死板容器：当源文件对于某章节特定小项未给出数据时，系统绝不凭空臆造、也不保留大段空白行，必须执行**“无值即删行，编号自适应连续重排”**。

此前系统仅对 Section 9（理化特性）开放了删行剪枝，而 Section 2（危险性概述）仍保留了模板初始所有未匹配行。当清零后空行遇到带有 `rowspan=5` 的复合合并格（`2.8 健康危害`）时，前端渲染跳行与 Word XML 底层跨行结构脱节，造成严重的“列挤出（Column Spillover）”，把后序行的标签推到了第二列、内容推到了第三列。

```
[原始模板 Section 2]
  Row 1: 2.1 紧急概述 [无值]
  Row 2: 2.2 GHS类别 [有值]
  ...
  Row 9: 2.8 健康危害 (rowspan=5) | 吸入 [无值]
  Row 10..13: 食入/皮肤/眼睛/症状 [无值]
  Row 14: 2.9 环境危害 [无值]
  Row 15: 2.10 其他危害 [有值]

  【此前缺陷行为】
  前端通过 isEmptyRow 静默隐藏空行，但 Row 9 的 rowspan 仍为 5！
  Row 9 的 rowspan 强行向下跨越到原本属于 Row 14 (2.9) 和 Row 15 (2.10) 的区域！
  导致：
  ┌───────────────────────┬─────────────────────────┬──────────────────────┐
  │ 列 1 (Col 0)          │ 列 2 (Col 1)            │ 列 3 (溢出 Col 2)    │
  ├───────────────────────┼─────────────────────────┼──────────────────────┤
  │ 2.8 健康危害 (跨5行)   │                         │                      │
  │ (向下穿透占用 Col 0)  │ 2.9 环境危害 (被迫挤入) │ [空白/溢出]          │
  │ (向下穿透占用 Col 0)  │ 2.10 其他危害 (被迫挤入)│ 无适用资料 (被迫挤入)│
  └───────────────────────┴─────────────────────────┴──────────────────────┘

  【本次重构修复后行为】
  通过底层真实物理删行 (deleteRow)：
  Row 1 (无值) -> 物理删除
  Row 4-8 (无值) -> 物理删除
  Row 9-13 (2.8 全部途径无值) -> 物理整块删除
  Row 14 (无值) -> 物理删除
  只保留有值行：
  ┌───────────────────────────────────┬──────────────────────────────────┐
  │ 列 1 (Col 0) - 标准第一列         │ 列 2 (Col 1) - 标准第二列        │
  ├───────────────────────────────────┼──────────────────────────────────┤
  │ 2.1 GHS危险性类别：               │ 根据GHS不属于危害化学品          │
  │ 2.2 GHS标签要素：                 │ 根据GHS不属于危害化学品          │
  │ 2.3 其他危害                      │ 无适用资料。                     │
  └───────────────────────────────────┴──────────────────────────────────┘
  连续自适应重新编号，仅有两列，完美对齐！
```

## 2. 详细技术方案

### 2.1 Section 2 专属删行与跨行合并维护算法 (`smart-matching.js`)

在 `applyMatchResultToEditor` 中增加 Section 2 的专属性审阅与删行处理：
1. **收集 Section 2 中有有效值的槽位集合**：
   - 从 `matchedSec.matchedRows` 中找出 `status === 'MATCHED' || status === 'NOT_APPLICABLE'` 且 `value` 非空的槽位项集合；
2. **特殊处理 2.8 复合合并块**：
   - 识别属于 `2.8 健康危害` 的所有子行（行索引 9-13，包含吸入、食入、皮肤、眼睛、症状体征）；
   - 统计这些子行中是否有任何一行匹配到了有效值：
     - 若**全部无值**：将 5 行全量加入 `rowsToDelete`；
     - 若**部分有值**：仅将无值的子行加入 `rowsToDelete`。对于保留的首行，将其父单元格（`2.8 健康危害`）的 `rowspan` 和底层 XML `<w:vMerge>` 严格更新为实际保留的子行数，确保跨行数与实际行数绝对一致。
3. **处理单行槽位**：
   - 对于 Section 2 的其他行（2.1 紧急概述、2.2 GHS类别、2.3 标签要素、象形图、信号词、2.5 危险性说明、2.6 防范说明、2.7 理化危险、2.9 环境危害、2.10 其他危害）：
   - 若对应槽位未匹配到有效值（或值为空白），将其加入 `rowsToDelete`；
4. **自底向上物理删除与序号重排**：
   - 将 `rowsToDelete` 逆序排序后循环调用 `deleteRow(editorEngine, tRecord, rIdx)`；
   - 删除后自动执行 `renumberRecord(tRecord)`，保持序号连续（从 2.1 开始顺延递增）。

### 2.2 渲染层几何防御 (`main.js` & `render-utils.js`)

1. **统一单一事实来源**：
   - 移除 `logicalTableRows` 中仅凭 `isEmptyRow` 假删除行却不修正 `rowspan` 的脆弱逻辑；
   - 渲染时的行结构与底层引擎的 `record.rows` 保持严格对应；
2. **跨行合并溢出安全校验**：
   - 在渲染 `<td rowspan="...">` 时，校验 `rowspan` 是否超过了表格后续剩余可用行数。若超过，自动截断限制为 `maxPossibleSpan = totalRows - currentRowIndex`，坚决杜绝 `rowspan` 越界溢出导致后续行产生第三列。

## 二、 三套产出链路全景解构

深入排查 `web/scripts/`、`web/src/` 与历史交接文档，目前在仓库中实际运行的产出链路共有 3 套：

### 1. 链路 A：当前正统权威的标准化覆写流程 (Canonical Pipeline)
- **核心载体**:
  - `web/src/pipeline-engine.js` 中的核心主函数 `executeEightDeliverablesPipeline`；
  - `web/src/smart-matching.js` + `msds-db.js`（源事实识别 + 品类基准数据库缺省值补全）；
  - `web/src/universal-editor-primitives.js`（双实体预设注入与 420/560 dxa 标尺、激光单 Tab 制表位投影）；
  - `web/src/pdf-converter.js`（调用 Windows 原生 WPS/Office COM 自动化组件进行 PDF 导出）；
  - `web/scripts/audit_bipolar_bilayer.mjs`（双极双层法医级深度主审计）。
- **流程特征**:
  - 严格遵循 7 步标准 SOP，从源事实解析 -> 智能基准补全 -> 中文基准构建 -> 英文基准翻译 -> 实体绑定 -> 排版几何投影 -> WPS COM 矢量转储。
  - 产出物稳定为 5 页，中英文双语严格 1:1 对应，模板样式保真度 100%。

### 2. 链路 B：历史遗留单体 CLI 脚本链路 (Legacy Monolithic CLI)
- **核心载体**:
  - `web/scripts/run_universal_msds_pipeline.mjs`
  - `web/src/recognition-engine.js` + `web/src/context-governor.js`
- **致命缺陷**:
  - 严重依赖旧时代僵硬的单组硬编码正则表达式；源文件键名一旦不是标准的“中文名称：”而是“产品名称：”，或者表格行列略有浮动，正则瞬间失效；
  - 识别失效后，直接落入“无危险性”或“无数据”分支，触发激进剪枝或留下大片空行。

### 3. 链路 C：外生 Python/Node 暴力裸改链路 (Rogue Ad-Hoc Patching)
- **核心载体**:
  - `web/scripts/apply_pa4914_full_fixes.py`、`verify_final_patched.py`、`test_build_oel_rows.py` 等。
- **产生根因**:
  - 当外部 Agent 执行任务时，发现链路 B 生成的产物由于源文件非标导致 Section 8、14 缺少内容、审计红灯；
  - 但 Agent 误将“禁止修改底层代码”当成了不可逾越的死令，不敢去调试或调用底座官方的 `pipeline-engine.js`，反而绕开底座，用 `python-docx` 编写独立的后处理补丁脚本，暴力修改 DOCX 内部 XML 并调用 LibreOffice 命令行硬转 PDF。

## 三、 为什么很多 Agent 即使使用 Test Kit 也走偏？

审查 `F:\App Location\Guanzhi Tong\Skill\MSDS-Engine\体系交接文档\MSDS_Studio_Agent_Test_Kit`，发现了三大结构性原因：

1. **Test Kit 缺失“可执行脚手架 (Runnable Runner)”**：
   - 当前 Test Kit 目录仅包含说明文档、企业预设、提示词规范及模板、源文件，**根本没有提供任何可直接执行的入口脚本（如 `run_standard_production.mjs` 或 CLI）！**
   - 外部 Agent 面对一个只有文本文档和模板的目录，根本不知道底座核心引擎 `pipeline-engine.js` 的存在，只能八仙过海、各显神通，自己写 Python 或单体脚本拼装。
2. **“底层代码绝对只读”禁令被教条化、负向化理解**：
   - 规则中强调“`web/src/` 底层代码绝对只读零篡改”，导致外部 Agent 哪怕发现了正则提取缺陷或缺省值映射缺陷，也“不敢碰底座”，只能在外面套娃写 Python 补丁（链路 C）。
3. **缺乏统一的数据适配器 (Input Adapter)**：
   - 外部 Agent 面对非标源文件时，不知道如何将非标事实结构化输入给底座，最终各写各的硬编码事实字典，导致代码极其碎片化。

## 四、 用户指出的关键 Bug 底层根因技术穿透

### 1. Word-PDF 异常转换（生硬写进、13 页膨胀）
- **技术穿透**:
  1. `apply_pa4914_full_fixes.py` 在修补表格单元格时，执行了：
     ```python
     def set_cell_paragraph(tc, text, ...):
         for p in tc.xpath('.//w:p'):
             tc.remove(p)  # 致命摧毁：清空了底模原有的所有 paragraph 属性！
         p = OxmlElement('w:p')
         ...
     ```
     这直接抹杀了单元格原生的段落内边距 (`<w:tcMar>`)、行间距、制表位与表格防溢出属性。
  2. 转换引擎脱轨：绕过了官方的 `pdf-converter.js`（调用 Windows 本地 `WPS.Application` COM 组件），擅自调用了 `C:\Program Files\LibreOffice\program\soffice.com --headless`。
  3. LibreOffice Headless 在缺少 Windows 字体度量与 Word 紧凑表格流排算法的情况下，对被剥离样式的 OpenXML 表格进行了极度激进的自动换行与换页，最终将 5 页内容撑爆成了 **13 页**，且排版粗暴生硬！

### 2. 大部分源文件内容缺失与未剪枝
- **技术穿透**:
  - **大部分未剪枝 (如 HPU-7651)**：
    底模 `正式模板_MSDS_CN_冠志(1).docx` 的 Section 2 自带 **16 行**（包括 2.1 紧急情况、2.7 物理化学危险、2.8 吸入/食入/皮肤/眼睛/体征、2.9 环境危害、2.10 其他危害）。老引擎若源文件中没有这些内容，仅仅是把右侧单元格置空，**没有调用 `deleteRow` 进行结构剪枝**，导致 16 行空虚线表格完整遗留在正式产出物中！
  - **大部分源文件内容缺失**：
    旧正则引擎仅针对标准 key 进行提取。当源文件表述为“产品形态”、“组分信息”、“操作处置”等微小变体时，正则全部漏抓，导致 Section 8、11、13、14 全为 null，直接被丢弃。

### 3. Section 2 通栏分割线异常
- **技术穿透**:
  - 底模中 Section 2 每一行都是双列，且单元格下边框定义为 `w:bottom w:val="dotted"`。
  - 当外部脚本尝试将其改为“通栏”时，如果仅仅合并单元格或写入单列，但未在 `<w:tcBorders>` 中显式指定 `top="none"` 和 `bottom="none"`，Word 就会默认继承底模的 `dotted`（虚线）或绘制内部横线。
  - **正规规范**:
    必须如官方 `pipeline-engine.js` 中的 `renderFullWidthRow`：
    - 彻底重构 `<w:tcPr>`，注入 `gridSpan="2"` 与 `w:tcMar`（上下 160 dxa 呼吸留白）；
    - 第一行数据行：`top="single"`, `bottom="none"`；
    - 中间数据行：`top="none"`, `bottom="none"`；
    - 最后一行数据行：`top="none"`, `bottom="single"`；
    - 绝不允许在中间数据行产生任何横向边框！

## 五、 正规化覆写标准流程与长效治理方案

### 1. 明确当前唯一的法定标准覆写流程 (Golden 7-Phase Pipeline)

标准 7 步生产流程：
- **Phase 1: 物理源文件事实感知 (Context 1)**：深度解析源文档，提取化学事实指纹；
- **Phase 2: 双实体预设加载与意图对齐**：加载冠志/国彩企业预设矩阵；
- **Phase 3: 事实标准化治理与基准补全 (Context 2)**：调用 `smart-matching.js` + `msds-db.js` 补齐缺省值；
- **Phase 4: 模板加载与前置值格清零**：清空底模历史死数据；
- **Phase 5: 编辑器受控写入与排版几何投影**：420/560 dxa 标尺、单 Tab、Section 2 纯净大通栏、Section 15 标准法规；
- **Phase 6: Windows WPS 原生 COM 高保真矢量 PDF 转换**：严格控制为 5 页像素级复刻；
- **Phase 7: 两阶双轨集中式主审计核销**：`audit_bipolar_bilayer.mjs` + `run_master_msds_audit.mjs`，退出码 0 门禁。
